# 本项目术语对照表（黑话 → 人话）

> 用途：`plain-talk` skill 翻人话时查这张表。
> **「不能删」列是硬约束**——翻的时候这些限定必须跟着走，丢了就变成假话。
> 新术语随时加；加之前先确认这个词不是一次性说法。

| 黑话 | 人话 | 不能删的限定 |
| --- | --- | --- |
| 契约 / `contracts/api.json` / v0.5 | 前后端约定好的一份接口清单，第 5 版 | 说清"这是约定不是现状"——清单里有的接口不一定都跑过 |
| 14 路径 / 55 schema | 14 个接口 / 55 个数据格式 | 路径数是清单上的数，不是"测过 14 个" |
| 信封 `{Code, Message, Data}` | 知乎接口统一的回包格式：`Code` 是状态码，`Message` 是文字说明，`Data` 是数据 | `Code=0` 才是成功 |
| 问题发现额度 | 每天从知乎「找问题」的调用次数（每天 100 次） | 这是**最紧**的一组：找问题和取回答摘要**共用**这 100 次 |
| 直答 | 知乎自己的 AI 问答接口 | 它只会改写你喂给它的材料，**不会自己去知乎搜** |
| 收藏 / 收藏夹 | 知乎上你自己存的内容 | 收藏里**多数是专栏文章**，不是问答，不能直接当"问题 + 回答"用 |
| 额度组 | 某一类接口共享的每日调用次数 | 说清是"共用一组"，不要让对方以为每类各有各的额度 |
| 缓存命中 / 5 分钟 | 同一个主题 5 分钟内再问一次，直接用上次结果，不再花额度 | 只省额度，**不保证**内容是此刻最新的 |
| 出处三件套 | 一张卡片必须能指回原文的三样：问题标题、问题链接、原回答链接 | 三样缺一就**不生成这张卡**——这是赛规查的点，不是审美选择 |
| 情境题 | 用知乎上真实问题和真实回答改写出来的场景题 | 题面由模型改写，但**出处字段全部来自接口，不由模型生成** |
| 同题两答 | 同一个知乎问题下的两条不同回答 | 数据层能证明"同题不同答"，**给不出作者名和立场** |
| 断层 / 语气（gentle） | 产品里那个"照镜子看自己说话方式"的效果，和它温和的那套措辞 | 语气是产品的一部分，不是可选项 |
| `SourceCard` / `kind: knowledge_card` | 卡片这个数据格式 / 卡片这一种类型 | 卡片和情境题**共用一套格式**，前端一套渲染逻辑 |
| OAuth / Access Secret | 两种不同的知乎身份凭证 | OAuth 是"每个用户登录自己的账号"，Access Secret 是"开发者账号" |
| 开发者账号模式 | 没登录时，接口读的是开发者账号的数据 | 这是**降级**不是默认体验，要说清"读到的是谁的收藏" |
| 决策 D1—D46 / ADR | 决策记录，一条改动为什么这么做 | 决策**只增不改**，推翻旧结论要写"已撤销" |
| 自检 PASS 13 / WARN 0 / FAIL 0 | 13 项检查全过，没有警告也没有失败 | 0 个 FAIL 才是能提交的前提 |
| 预检 / 部署包 / 白名单打包 | 上传前先查一遍 / 打包好的可上传文件 / 只打包该打包的文件 | 预检里有一项是**把本机密钥读进去比对包里有没有它**——结论要一起说 |
| 拍 / 边界态（Demo 脚本） | 演示脚本里的一个节拍 / 一个特殊界面状态 | **台词不许早于事实**：不能念屏幕上还没发生的事 |
| 冒烟脚本 / 回归 | 快速试一遍主要功能能不能跑 / 把整条演示流程按顺序跑一遍 | 回归**会烧额度**，跑之前先看额度 |
| CrashLoop 空白页 | 服务起不来，浏览器只显示白屏 | 这类问题**本地看不出来**，在评委机器上才现形 |
| 零 G / 零 H / 零 K | 计划里还没发出去的三条消息（分别是开工手册、追问、补充说明） | 目前**只有零 I 真的发出过**，其余由人自己发 |

## 数字怎么念

| 原文 | 说人话 |
| --- | --- |
| 额度 0/100 | 今天的调用次数已经用完，明天 0 点恢复 |
| 额度 88/100 | 还剩 88 次，不够就得等明天 |
| PASS 13 / WARN 0 / FAIL 0 | 13 项检查全过，没有警告也没有失败 |
| 14 路径 | 前后端约定好的 14 个接口 |
| v0.5 | 接口清单第 5 版 |
| 11 次问题发现 | 完整跑一遍要花掉 11 次「找问题」的额度 |
| 9 条收藏 | 账号里存着 9 条知乎内容 |

## 容易翻错的地方

- **「额度耗尽」不是 bug**，是**用完了**——翻成人话不能说成「有一个功能坏了」。
- **「修了 3 个 bug」≠「3 个 bug 都好了」**——修完没验证过，只能说"改了"，不能说"好了"。
- **「未验证」不能变「已通过」**；项目里区分事实 / 推断 / 建议 / 缺失四类，人话版也要标。
- **「计划」不能变「已经做了」**。
- **「缓存 5 分钟」不能翻成「总是最新的」**。
