## 跑起来

需要**两个进程**（前端不打包、不依赖任何 npm 包，零依赖）。

```powershell

cd 'C:\Users\steam\Desktop\从心\server'
$env:ZHIHU_ACCESS_SECRET = (Get-Content -Raw 'C:\Users\steam\.zhihu-cli\access_secret').Trim()
$env:PORT = '18787'; node src/index.js

# 2) 前端
cd 'C:\Users\steam\Desktop\从心\web'; node serve.js
```

打开 **<http://localhost:18788/web/>**。

### 部署形态：**一个进程 = 完整作品**（D42，11-19 补上）

后端进程会**同进程**挂上前端静态，所以不用起第二个服务也能玩：

| 地址 | 是什么 |
| --- | --- |
| `http://localhost:18787/web/` | **后端自己发的页面**（部署形态，开发期也能开） |
| `http://localhost:18787/` | 302 → `/web/` |
| `http://localhost:18787/assets/kanshan/*.webp` | 素材（刘看山 WebP） |
| `http://localhost:18787/api/*` | 11 个接口（**同源**，前端不用改一行） |

- **只挂 `/web/` 与 `/assets/` 两个目录**，不挂仓库根 —— `docs/`、`server/` 源码、`.ctx/` **不暴露**。
- 仓库根**按 `web-static.js` 自己的位置算**（server/src/lib → 上溯三层），**不看工作目录** ——
  容器里的工作目录不一定是代码根（11-21 改，去掉了 `WEB_STATIC_ROOT` / `WEB_STATIC` 两个环境变量开关：
  官方交付规范不允许运行期读自定义环境变量）。
- 挂载顺序有讲究：**接口路由之后、404 兜底之前**——反了 `/api/*` 会被静态吃掉。
- 部署到知乎 AI Works（源码发布）时就是 `npm install && npm start`（仓库根有 `package.json`），
  监听 `0.0.0.0`、端口读 `PORT`（fallback 9000）。
  **密钥走文件**（官方 11.7「秘钥写入文件直接构建」），**仓库与仓库历史里都没有它** ——
  暴露面与处理方式见 [`docs/部署指南.md`](../docs/部署指南.md) 第 3 节。

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `WEB_PORT` | `18788` | 前端端口 |
| `API_BASE` | `http://localhost:18787` | 后端地址（`serve.js` 把它代理成同源 `/api`） |

**为什么要代理**：页面与接口同源 → 前端不用处理 CORS，也不用在前端里写死后端地址；
部署时（AI Works）前后端同进程，把静态目录挂到主服务上即可，**前端一行不用改**。

### 演练模式

决赛只有 5 分钟，中途点错一下就断节奏。

| 地址 | 作用 |
| --- | --- |
| `?demo=1` | 自动跑一遍 Demo 脚本骨架（喂材料 → 吐卡片 → 补观点 → **翻到「问它」→ 抛问题 → 出方案**） |

> ⚠️ **演练也会真调知乎**：
> - 「喂它收藏」吃**用户数据**额度；
> - 「知乎上大家怎么说」吃**问题发现**额度（**N 张卡 ≈ 1+N 次**）；

>

>

> **直答只剩 83/100，比问题发现更紧**（问题发现 100/天 且已被旧链路烧掉不少）。
> **演练前先看一眼 `/api/quota`。**
>
> 📌 **11-19 旧口径已作废**：「一次完整演练 ≈ 11 次（3 张主流程卡 + 2 张观点卡 + 情境题）」「11-18 22:59 问题发现只剩 13/100」

### 桌宠运动分三层（别合并）

| 层 | 负责 | 实现 |
| --- | --- | --- |
| 素材自身 | 角色动作（挥手 / 电波 / 运球…） | `assets/kanshan/*.webp`，本身是**动画 WebP** |
| `.petfigure` | 跟随指针的倾斜与位移 | CSS 变量 `--pet-tilt/--pet-shift/--pet-lift` + `transition` |
| `.petanim` | 循环与一次性动画（呼吸 / 摇摆 / 弹跳 / 垂头 / 落地 / 点头） | `@keyframes` |

- **为什么必须拆两层**：`animation` 会**整体覆盖** `transform`。写在同一元素上时，只要呼吸在跑，鼠标跟随就被整个顶掉。
- **红线**：`transform` / `filter` 一律不许作用在 `<img>` 上（动画 WebP 逐帧重新合成 → 白边与残影，11-19 实拍 / D39）。改动桌宠时先用 devtools 确认 `getComputedStyle(img).transform === 'none'`。
- **支点统一 86% 高度**（接近脚），缩放才读作「踮脚 / 呼吸」，而不是整张图胀缩。
- **`prefers-reduced-motion` 全关**：`.petanim` 动画、跟随绑定、换图收放全部跳过；素材自身的帧动画照旧。

### 第二轮（2026-11-18 22:0x—22:5x）：补 4 个缺口

用户拍板「**只补 4 个缺口，不改形态**」（保留「工作台」形态，不改成脚本的「演出」形态）

| # | 缺口 | 怎么实现的 | 实测结果 |
| --- | --- | --- | --- |
| 1 | **主流程卡片不是真的** | 改走 `POST /api/cards`：每张卡 = 知乎问题 + 真实回答 + **原回答 URL** | 3 张真卡片，带 `www.zhihu.com/1977304008017331977` 这类真实链接，点开就是知乎原回答 |
| 2 | **台词只用了 9 句** | 新接 `offer` / `source` / `viewpoints` / `disagree` / `park` / `closing` | **契约 14 句全部用上**（逐句抓气泡验过） |
| 3 | **收藏不能拖** | 收藏条目 `draggable="true"`，桌宠 `#pet` 变成 drop 目标 | `dragover` 时桌宠亮起 → `drop` → 嚼出 3 张带出处的卡片 |
| 4 | **桥画不出来** | 桥是**跨层**的，原来根本没有画法 | 按块在**屏幕上的实际位置**（`getBoundingClientRect`，含 perspective 投影）跨层连线；实拍 **3 座绿虚线桥** |

**这一轮补进去的两个关键细节**：

- **主题词要挨个试，不能只猜一个。** 知乎搜不到就诚实返回空 → 前端必须**真的换个说法再试**。
  候选全部来自真实数据，按可靠性排序：**收藏里 `answer` 型条目的标题**（它本身就是知乎问题标题，最可靠）
  → 标题剥掉体裁词后的短语（「软件测试笔记」→「软件测试」）→ n-gram 兜底。最多试 4 个，**单个失败不算整段失败**。
- **没有出处的卡不说「这是知乎上真有人写过的」。** `source` 台词挂在卡片上，
  但本地拖进来的材料卡没有 `a.src[href]` → **不触发这句**（那不是知乎上写的）。

回归结果：`?demo=1&fast=1` **9/9 步全过、0 报错**；
单独又验了拖拽落桌宠、`viewpoints`→`disagree` 两拍台词、跨层桥。
