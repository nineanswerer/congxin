# 契约层 — 不可变事实

> 这份文件回答一个问题：**什么东西改了会让另一个人的环境静默出错？**
> 机器可读版本在 [`contracts/contract.json`](contract.json)，`scripts/check-contract.ps1` 按它自检。
> **两份文件冲突时以 `contract.json` 为准，并立刻修正本文件。**

## 变更规则

1. 本目录**只增不改**。事实变了就写一条新的 ADR 说明"旧事实作废"，不要原地改写历史。
2. 任何改动必须同时更新 `contract.json` 和本文件，且在同一次提交里。
3. 改完跑 `powershell -ExecutionPolicy Bypass -File scripts/check-contract.ps1`，FAIL 就不能提交。
4. 涉及赛程、额度、合规红线的改动，**必须两个人都知道**——改完在群里说一句。

## 接口契约（`api.json`）

[`api.json`](api.json) 是**我们自己的后端**对外的接口形状，写成 **OpenAPI 3.1**，前端可以直接
`openapi-typescript` 出类型、`@mswjs/openapi` 起 mock，**不需要手写 mock，也不需要知道知乎开放平台的任何细节**。

| 接口 | 作用 | 上游 |
| --- | --- | --- |
| `GET /api/behavior/favorites` | 收藏信号（收藏跨度 + 结构占比） | `user/collections` + `user/favlists` |
| `GET /api/behavior/followees` | 关注信号（关注对象类型分布） | `user/followees` |
| `GET /api/behavior/contents` | 创作信号（论证结构 + 活跃度） | `user/contents` + `user/creator_account_stats` |
| `POST /api/behavior/tension` | **张力信号**：自述 vs 行为 → 断层 | 复用上面三个接口的结果 |
| `POST /api/situation/question` | 情境题生成（**每题必带知乎出处**） | `user/question_recommendations` + `content/question_answers` + 直答 |
| `GET /api/terrain` | 三层认知地形（说的你 / 做的你 / 情境下的你）+ 断层 + 桥 | 派生，不调上游 |
| `POST /api/terrain/answer` | 提交情境题回答 → 地形生长 | 派生，不调上游 |
| `GET /api/quota` | 额度透传 | `quota` |
| `GET /api/tone` | **桌宠语气目录 + 全部台词**（语气切换器用） | 不调上游，读契约层 |
| `GET /api/auth/profile` | 当前登录用户资料（昵称 / 头像 / 一句话介绍），**两种模式** | `openapi.zhihu.com/user`（仅 OAuth 模式） |
| `GET /api/auth/login` | 发起知乎授权（302 跳转） | `openapi.zhihu.com/authorize` |
| `GET /api/auth/callback` | 授权回调：换 token、建会话（302 回前端） | `openapi.zhihu.com/access_token` |
| `POST /api/auth/logout` | 退出登录、清会话（幂等） | 不调上游 |
| `POST /api/cards` | **知识卡片产出**（咀嚼 → 吐带出处的卡片） | `user/question_recommendations` + `content/question_answers` |

**产品结构（2026-11-17 方向已定）**：**桌宠是交互主体**，「认·清」认知闭环是桌宠里的**一个功能环节**，
不是另一个产品。两条线共用同一批知乎原料接口 —— 认知闭环的后端代码与主流程是同一份。

**渲染责任**：**后端只给参数**（归一化坐标、高度、强度、置信度），**前端负责渲染**。
2.5D 分层地图用 SVG + CSS `perspective`，断层特写处用 Three.js 做一次真实推镜。

三条硬规则（对应 `AGENTS.md` 第 3 节与官方提交前检查第 7 条）：

1. **不生成没有出处的内容** —— `source` 必填，拿不到真实问题标题 + URL + 原回答链接就报错。
2. **空数据 ≠ 失败** —— 空数据走 200 + `empty: true` + `empty_notice`，前端显示真实提示。
3. **失败必须是真话** —— 统一错误信封，`user_hint` 是中文、给人看的，不允许空字符串或英文原始报错。

外加一条**认知闭环专属底线**：**至少 2 个独立可用的行为信号，断层才成立**。只有 1 个时必须返回
`insufficient: true` + `insufficient_reason`，**不许拿一个信号硬撑出断层**。

## 登录（OAuth）

**凭证从哪来**：App ID / App Key **由赛事页面在项目创建后分配**，黑客松**不走通用邮件申请流程**
（官方原话：「尚无凭证时，不要编造提前领取入口，也不直接套用通用应用的邮件申请流程」）。
**App ID / App Key 与 Access Secret 不是同一个东西**，三者职责不同。

**`GET /api/auth/profile` 永远返回 200，但有两种模式**（看 `data.mode`）：

| mode | 什么时候 | 前端怎么显示 |
| --- | --- | --- |
| `oauth` | 用户授权过知乎（12-05 拿到凭证之后） | 用真实昵称、头像、一句话介绍 |
| `developer_account` | 开发期没有 OAuth 会话 | 昵称等字段为 null，显示通用称呼 |

**不许在 `developer_account` 模式下编一个昵称**——官方提交前检查第 6、7 条查的就是假数据与假身份。

**OAuth 的协议坑**（官方自己标了「待确认」，实现前必读）：

1. 回调参数叫 `authorization_code`（**不是** `code`），但换 token 的表单字段又叫 `code`——接收端两个都得收。
2. **回调不返 `state`** → 做不到标准登录 CSRF 校验，上线前必须向平台确认。
3. **只有 `access_token` + `expires_in=3600`，没有 refresh token** → 1 小时必过期。
4. `/access_token` 与 `/user` 响应里 **`code: 20000` 表示成功**，别当错误。
5. Token 过期或鉴权失败时**停止读取**，不静默切回 Access Secret 所属账号。
6. 创作能力四项（我的全文 / 评论 / 账号统计 / 单篇统计）**不支持 OAuth 身份切换**。

**`uid` 超过 JavaScript 安全整数范围**：后端按字符串返回，前端按字符串处理，不要先转 Number 再转字符串。

## 知识卡片（`POST /api/cards`）

**主流程那条链的第一块砖**：拖入资料 → 咀嚼 → 吐卡片 → 点开原文 → 追问 → 知乎补观点 → 卡片列表。

**一张卡片 = 一个知乎上真实存在的问题 + 它下面一条真实回答的官方摘要 + 原回答链接。**
形状沿用已有的 `SourceCard`（`kind: knowledge_card`），**不新造一套**——卡片与情境题共用同一个对象，
前端一套渲染逻辑。

**出处三件套是硬约束**（`SourceRef` 契约层已经把它写成必填）：

| 字段 | 来自哪个上游 | 说明 |
| --- | --- | --- |
| `question_title` | `user/question_recommendations` | 知乎真实问题标题 |
| `question_url` | `user/question_recommendations` | 知乎问题完整 URL |
| `answer_url` | `content/question_answers` | **原回答链接**——回跳出处的关键 |
| `answer_summary` | `content/question_answers` | 官方服务摘要（**不是 AI 生成**，前端别标成「AI 总结」） |

**拿不到原回答链接就不生成这张卡**（官方提交前检查第 6、7 条查的就是没有出处的卡片）。
主题来自请求参数（用户拖进来那份资料是关于什么的），**前端不内置任何素材**，每次跑出来都是实时知乎数据。

**为什么只能走问题发现链路**（2026-11-18 实测）：原回答 URL **只有** `content/question_answers` 能给。
收藏接口给不了——实测该账号 9 条收藏里 **8 条是专栏文章**（`zhuanlan.zhihu.com/p/...`），
剩下 1 条的 URL 是 `zhihu.com/answer/xxx`，**推不出问题 URL，也没有原回答 URL**。

**额度**：走「问题发现」额度组（100 次/天，与情境题共用）。
一次 `question_recommendations` 出最多 20 个问题（1 次调用），每个问题再花 1 次 `question_answers`
→ **N 张卡 ≈ 1 + N 次**。后端**按主题缓存 5 分钟**，同一主题重复演不再打上游。

## 分类体系（`taxonomy.json`）

**后端算、前端显示并高亮**——这是跨两个人的接口，所以口径必须只有一份，放在契约层。

- **主题分类**（6 类）→ 用于**收藏**与**关注**：`tooling` 工具与环境 / `engineering` 工程与方法 /
  `ecosystem` 资讯与生态 / `knowledge` 知识管理 / `cognition` 认知与判断 / `career` 职业与行业
- **论证结构分类**（5 类）→ 用于**创作**：`problem_solution` / `definition` / `contrast` / `steps` / `example`
- **两套不要混** —— 一个是"用户在关心什么"，一个是"用户怎么表达"。
- **命中 0 条落 `unknown`（未归类）**，是合法结果，**不许硬塞**。
- **同分即弱结论** —— 第一名与其它类同分时（返回 `tied` / `tied_with`），只是**数组顺序**取胜，
  不能说成"集中在某类"。后端已经在 `focus.summary` 和 `sample_note` 里如实写明。
- **上游摘要会被截断** —— `/api/v1/user/contents` 返回的 `Summary` 末尾带省略号（实测创作被截在
  「…事后…」），基于摘要的分类**只覆盖原文的一部分**，提示里必须说明这一点。
- **改关键词表后必须跑回归**：`node server/scripts/classify-check.js`（比人工标注基线）。
- 说明与真实数据分布见 [docs/分类体系-B14.md](../docs/分类体系-B14.md)。

> 上游的实测细节（`Code=10001` 参数缺失、`Code=30001` 秒级限流、`NextOffset` 是字符串、
> **问题发现对全大写英文词召回不稳 → 主查 + 小写降级**）记在
> `api.json` 的 `x-upstream` 段，**后端要在这一层抹平，不要透给前端**。

## 语气（`tone.json`）

**文案写在契约层，后端与前端读同一份。** 前端**不要自己抄一份台词**——两份一定会漂，
而且换语气时前端那份必然漏改。

- **两个语气**：`gentle` 温和陪伴（默认）/ `lively` 活泼。
- **默认是 `gentle`** —— 用户 2026-11-18 拍板：「台词口语度做成可选项，且默认就是当前这版
  （温和陪伴），别把默认改成活泼的。」`scripts/check-contract.ps1` 第 13 项会机器校验这一条。
- **`GET /api/tone`** 一次给全：切换器的选项 + 当前语气的**全部 13 句台词**。
  4 个认知接口也都带 `tone` 与 `pet_lines`，按 key 取即可。
- **语气只影响桌宠自己说的话。** 断层 `label`、证据、`confidence_note` 是**数据陈述句**，
  由后端按真实数据生成，**不随语气变化**——换个口气不会让它更真，也不会让它更假。
- **台词里不许写数字结论。** 带数字的句子属于数据陈述；写进台词目录就会有两个真相源。
- **不认识的 `tone` 回落到默认，不报错** —— 前端传错不该让整条链路挂掉。
- 改台词后跑 `node server/scripts/smoke-tone.js`（**不消耗任何知乎额度**）。

### 技术底座

前端 + Node 单进程，**零数据库、零中间件**，会话存进程内 Map。
**理由**：官方 FAQ 明确"前端+Node后端且不含数据库写入的全栈项目"可用知乎 AI Works 部署；平台暂不支持独立数据库托管。

### 合规红线

1. Access Secret / App Key / OAuth Token **不得出现在源码、前端响应、日志、截图、视频**。
2. 刘看山 IP **仅本届比赛期间可用**，赛后禁商用；素材缺失时状态机降级为静态占位。
3. 接口失败、额度耗尽、空数据**必须给真实提示**，**绝不返回伪造兜底数据**。
4. 禁止批量、高频、无意义调用，禁止刷屏与重复投稿。
5. 不得使用任何已公开发布或已获奖项目的代码与成品。

## 为什么要有这一层

两个 AI 平台 = 两个互不相通的记忆体。Git 只记录"改成了什么"，
不记录"为什么这么改"和"试过什么失败了"。契约层把**跨环境会静默出错的东西**
显式写死，让换平台、换人、换机器之后不用靠读代码考古来猜。
