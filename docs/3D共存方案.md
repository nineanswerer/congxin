# 3D 与现有工作台「两者共存」落地方案（2026-11-28）

> 结论一句话：**3D 是入口与氛围层，现有工作台是功能与证据层，两页并存、互不替代；
> 真数据只有一处来源 —— 我们的 API。**
>
> 背景：队友交了两版 Three.js 3D 场景（`两个房间-卧室与书房` 165KB / `apartment.html` 四间房 321KB），
> 想把前端全部推翻改成 3D，并把功能映射到物件上、再加上 3D 桌宠。
> 用户判断「推翻不可行」，本文件按**两者共存**来算。

---

## 1. 为什么是共存，不是推翻

**事实（扫过两个文件）**：

- 两个文件里**没有「知乎」、没有任何 `/api/` 调用**，只有 localStorage + IndexedDB。
- 书房的 `session / materials / cards / feedback / unresolvedTensions / moodCurve` 全部来自 `mockData()`
  （文件自己的注释就写着「mock，字段名照后端 8 类实体」）。
- 而且它照抄的是**已经下线的认知闭环**（D66 之后主线是「问它」）。

**推翻的后果**：

| | 推翻（3D 当唯一前端） | 共存（3D 首页 + 工作台） |
|---|---|---|
| 真实内核（收藏→卡片→出处→同题两答→「问它」） | **落空**，界面完整但内容是编的 | 全部保留，3D 负责体感 |
| 硬线「出处必填 / 失败是真话 / 不允假数据」 | **撞线** | 不撞 |
| `ui-contract.json` 33 个 id | 全部失效 → `check-contract.ps1` 界面契约项 FAIL | 不动 → 仍 PASS 14 |
| 演示视频 | 已出的 97.6 秒成片作废 | 保留，3D 就位后重录一版即可 |
| 12-04 前主链路冻结（D74 §8） | 破 | 不破 |
| 要队友返工 | 书房整块重写 | 只把 `mockData` 换成真实 API 形状 |

**一句话**：3D 解决"情感的体感"，知乎数据解决"证据的可信"。两件事不该互相顶替。

## 2. 共存架构

```
/web/            ← 现有工作台（不动）：卡片 / 观点 / 问它 / 台词气泡
/web/3d/         ← 新增 3D 首页（队友的活）：卧室·书房·客厅·厨房，点物件开卡片
      │  点「去做这件事」→ 深链进工作台对应面板
      │    /web/?tab=flow&panel=cards     （收藏 → 卡片）
      │    /web/?tab=flow&panel=views     （同题两答）
      │    /web/?tab=mirror               （问它）
      └──────── 工作台右上角加「回 3D」小按钮 ← 原路返回
```

- **契约影响**：3D 是新增页面，不进 `ui-contract.json`；工作台的 33 个 id 一个不动
  → `scripts/check-contract.ps1` 仍 **PASS 14 / WARN 0 / FAIL 0**。
- 3D 页与工作台同源部署（同一个进程挂 `/web/` 静态），`/api/*` 走同一套后端，不新增部署形态。

## 3. 物品 ↔ 真实接口 对照表（**给队友的施工单**）

> 规则：`ITEMS` 里每个物件的 `act` 要指到**下面某个真实接口**；
> 拿不到真实数据的物件，就只保留"氛围/导航"职责，**不许编内容**。

| 3D 物件（`ITEMS`） | 真实接口 | 界面上显示什么 | 出处字段（必须来自上游） |
|---|---|---|---|
| 挂画墙（`art` / `ART_SLOTS` 相框） | `GET /api/behavior/favorites` | 每张相框 = 一条**真实收藏**：标题、作者、内容类型 | `answer_url` / `question_url` → 点开跳知乎原回答 |
| 书桌 / 书架（书房 `study`） | `POST /api/cards` | 「喂桌宠」产出的知识卡片 + 出处角标 | `source.question_title` / `question_url` / `answer_url` |
| 书房书桌上的纸（`pick` 判断面板） | `POST /api/cards`（`same_question=true`） | **同题两答**：两条真实回答并排，不替用户选 | 两条各自的 `answer_url` |
| 床头的台灯 / 书架上的本子（`lamp2` / `night`） | `POST /api/advice` | **「问它」**：用户抛一件事 → 知乎找相似困境 → 判断适用性 → 给方案 | 每步的 `依据第几条` → 点开跳对应原回答 |
| 灯串 / 窗外天空（`string` / `window`） | `GET /api/tone` | 桌宠说话（**只用 14 句契约台词**）+ 昼夜 | 无（台词不是数据） |
| 门（`door`，`act:'door'`） | — | 房间切换（**已有**，纯导航） | — |
| 落地灯 / 地毯 / 拖鞋 / 窗帘 / 毛皮地毯 | — | 纯氛围，点击只开"制作说明"卡 | 无 |

**没有接口、必须处理的三处**（在队友的 `mockData()` 里）：

- `session.moodCurve`（情绪曲线）→ **无接口** → 删，或改成"由最近一次问答生成"，并标明是本地状态。
- `session.unresolvedTensions`（未解张力）→ **无接口** → 删（这是认知闭环的旧概念）。
- `materials` / `cards` / `feedback` → 认知闭环旧主线 → 换成上面的 `favorites` / `cards` / `views` / `advice` 四类真产物。

## 4. 三条不可破的规矩（写给队友）

1. **证据类内容只能来自 API。**
   `blurb` / `tips` 是"这个 3D 物件怎么做的"（**创作者视角的技术说明**，可以保留）；
   但任何看起来像"**你的**经历 / 你的收藏 / 知乎上有人说过的话"的内容，**必须来自接口**，
   且出处字段原样透传。**不得再新增 mock 证据。**
2. **桌宠台词 = `GET /api/tone` 的 14 句**，一字不改、不新增第 15 句
   （`contracts/tone.json` 是硬契约；认知闭环下线的 5 句保留但不调用）。
3. **3D 页面里不许出现"假数据"兜底**。
   接口空 → 显示真话（"这次没读到知乎上的数据"），不要用 mock 填坑。

## 5. 我们这边要做的三件（都不动工作台功能）

1. **工作台支持深链**：`web/js/app.js` 读 URL query 决定初始 tab / 面板
   （`?tab=flow|mirror`、`?panel=cards|views`）—— 小改动，不动契约里的 33 个 id。
2. **工作台加「回 3D」小按钮**（右上角），构成闭环。
3. **3D 页部署可行性实测**（必须实测，不许想当然）：
   - AI Works 上能不能跑 `importmap` + `import 'three'`（我们 D74 的 module-loader 自愈是为**自己那套** ESM 写的，不一定吃得住 importmap）；
   - `unpkg.com` 在国内 / 评委网络的可达性（建议改用国内 CDN 或本地内置 three.js）；
   - 单文件 165–322KB + three.js 的加载体积；
   - 手机 / 低端机帧率（2600 根毛簇 + InstancedMesh + `cloth()` + 程序化贴图）。

## 6. 视频

- 两者共存的视频结构：**3D 开头 ~15 秒**（进 3D 首页 → 点一个物件 → 点「去做这件事」→ 进工作台）

  3D 就位后重录**不烧任何知乎额度**，本机几分钟出片。
