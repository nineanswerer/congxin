## 2. 拿到 Access Secret（1 分钟，要你自己做）

1. 打开 <https://developer.zhihu.com/profile>，用**你的知乎账号**登录
2. 找到「申请新 Access Secret」，生成一个
3. 把那串值粘到 `secrets/access_secret` 文件里（步骤 0 已经建好这个目录了）

**规则原文口径**（见 [`rules-知乎S3.md`](rules-知乎S3.md) 14.3）：

- 单账号最多 20 个 Access Secret，**删了找不回来**
- **同一账号下的所有 Access Secret 共享额度** —— 所以你用你的账号申请，不占我那边的额度池
- **额度跟你有没有实名认证有关**：
  - **已实名认证**（有手机号 + 实名）→ 问题发现 100 次/天、直答 100 次/天、用户数据 10000 次/天
  - **未实名认证** → 问题发现只有 **10 次/天**（够完整跑一遍，但没法反复试）
- `App ID` / `OAuth App Key` 是**赛事页面按项目分配**的（12-05 之后才有），**开发期不需要**，别等它

**密钥红线**（官方提交前检查第 6 条，务必守住）：

- ❌ 不贴进 GitHub、不贴进群聊、不贴进截图、不念进演示视频
- ❌ 不写进任何提交的文件里
- ✅ 就放在 `secrets/access_secret` 这一个文件里（`.gitignore` 已覆盖，提交不上去）
- ✅ 录屏录屏时注意别把终端窗口框进去

## 4. 为什么我不直接把密钥给你

一句话：**评审看的是「我们俩能不能协作」，不是「密钥传得快」**。

更重要的是官方提交前检查第 6 条写着一句：

> 提交的体验账号不复用个人或生产管理账号。

我们自己人去搞自己的密钥、跑自己的数据，天然干净；如果整条演示链路都挂在一个人（我）的账号上，
公网链接里的收藏、关注、创作全是**我的个人数据**，这条就有风险了。

**你的 Access Secret = 你自己的收藏 = 你自己的体验数据**，这条链路对评审也更好讲。

## 5. 体验的时候，人眼要判三件（自动化测不了，只能人看）

这三条是你（或者任何真人）看的时候最该挑的毛病：

1. **5 分钟够不够**
   拿手机计时走一遍 `P1-三件产出.md` §二的逐秒脚本。超时就砍拍，不是加快语速。

2. **台词念着顺不顺**
   台词在契约层 `contracts/tone.json`（2 种语气 × 14 句）。哪句拗口、哪句不像人说话，
   记下来告诉我。**改台词要你说，我不自己动**（这是拍板过的规矩）。

3. **失败态的提示像不像人话**
   断网 / 额度耗尽 / 收藏为空时，页面给的是**真实提示**还是干巴巴的报错？
   官方第 7 条硬要求「接口失败、额度耗尽和空数据有真实的错误或降级提示」。
   这三处现在有真实提示，但**「像不像人话」得你说了算**。

**还有两条是「点得动吗」**：每张卡的出处能不能真的点开知乎原回答？同题两答是不是真的两个不同 `answer_url`？
**「问它」的出处是不是每一步都能点回对应的那条知乎原文？**（这一条是新主线上的重点）

## 8. 遇到问题怎么办

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| **启动终端里出现** `⚠️ 配置不完整 —— 没读到知乎 Access Secret` | 密钥文件没读到 | 这个警告只打在**终端的 stderr**，页面上看不到。检查 `secrets/access_secret` 存在、有内容、没有多余引号或空行 |
| 页面开了但卡片是空的 + 有中文提示 | 同上（另一种表现） | 同上；确认启动命令是在**仓库根目录**跑的（`npm start`），不是别的地方 |
| 提示「额度已用完」 | 你账号的问题发现额度用完了 | 等 00:00 重置（每日重置、不结转） |
| 端口起不来 | 18787 被占 | `Get-NetTCPConnection -LocalPort 18787` 看谁占的，或换个端口 `$env:PORT='18789'` |
| `npm install` 失败 | 网络 | 只需要一个包（express），重试或 `npm install --registry=https://registry.npmmirror.com` |
| 卡片点不开出处 | 少见 | 把链接贴给我，这是 bug，必修 |

**别自己 debug 超过半小时** —— 遇到问题直接甩我链接 + 报错原文，我这边复现快得多。
