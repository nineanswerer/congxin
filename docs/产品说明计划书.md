## 一、一句话

> **「从心」是一只住在你桌面上的知乎学习搭子。**
> 它把你收藏夹里吃不完的东西嚼成**每张都能点回知乎原话**的知识卡片；
> 你追问「知乎上大家怎么说」，它去把**同一个问题下真实存在的两条回答**摆到你面前——**它不替你选**；
> 它还会当场「照镜子」，把你**说的**和**做的**之间的那道断层指给你看。

- **作品名 / 队名**：从心
- **赛道**：**AI × 陪伴与交互**（官方 `project_tracks` value = 8）
- **形态**：Web 应用（前端 + Node 后端，单进程，零数据库零中间件）
- **仓库**：<https://github.com/nineanswerer/congxin>
- **可运行体验链接**：【待】正式公网链接（AI Works 审核通过后生成）
- **团队**：九术（队长）、张道哲

## 二、核心创作思路

### 2.1 桌宠是交互主体，知识卡片是它的产出物

产品的主次关系是刻意定下来的：**桌宠是交互主体**（有人格、有情绪、有反馈），**知识卡片是它的产出物**，**知乎开放能力是它的信息来源**。

这不是审美偏好，是被上届的获奖形态逼出来的决定：S2 一等奖 **MeetMind学脉**（清华，¥30,000）做的是「把收藏夹里的文章变成口播 + 板书，转为一对一老师式互动学习课程」——**「收藏夹 → 学习内容」这条路已经被占住了**。如果「从心」也做成「更聪明的卡片生成器 + 一个宠物皮肤」，评审的第一反应会是「这是 MeetMind 的降级版」，创新度（初审占 25%）会直接失分。

所以「从心」反过来做：**不是「更好用的收藏夹」，而是「一只陪你干活、并且会跟你较劲的桌宠」**。

### 2.2 一句话说清我们和上届的差别（创新度 25% 的落点）

> **MeetMind 把你的收藏变成一门课。「从心」把你的收藏变成一个会跟你吵一架、还会照镜子指认你断层的桌宠——它给的是知乎上真实存在的分歧，不是整理好的知识产品。**

展开成三件具体的事：

| # | 差异点 | 别人（典型知识整理工具 / 上届形态） | 从心 |
| --- | --- | --- | --- |
| 1 | **有出处的观点对照** | 给 AI 写的摘要 / 结构化知识点，出处是「参考来源 1、2、3」这种模糊指向 | 给**知乎上真实存在的不同答案及其原始回答链接**，用户看到的是分歧本身；**无法回跳原文的卡片不算数** |
| 2 | **问题反哺** | 工具只在你的私藏里打转 | 桌宠会指出「你这个主题，知乎上正在被问的问题」，把私人资料和公共讨论接上 |
| 3 | **陪伴而非工具** | 界面是一张表单，失败了就弹 toast | 桌宠对状态有反应：咀嚼、电波检索、打盹、**信号不足时它会明说「这次信号不够我下判断」** |

### 2.3 为什么值得用知乎的开放能力（而不是一个通用 LLM 就够了）

我们**故意不用直答 Agent 做观点比较**。官方 CLI 文档原话：

> 「搜索用于取得原始资料，直答用于快速获得总结，**深度研究、事实核查和观点比较不要用直答替代搜索**。」

因此主路径固定为 `问题发现（question_recommendations）` → `问题回答摘要（question_answers）`：后者直接返回**原回答链接**（上游响应里的 `Url` 字段），这正是「每张卡片能点回知乎原话」的技术基础。**直答只做快速解释与兜底**——这是方法论选择，不是额度问题。

官方能力表里对「问题发现」的定位原文就是「**观点对照**」，与我们的差异点 1 逐字对上。

## 三、场景价值

### 3.1 痛点（真实，不是想出来的）

用户自己写在知乎创作里的原话【实，11-19 实测取出】：

> **「我的收藏夹里有 200 篇 PDF，一篇都没用上。」**

这不是个别现象。我们账号的**真实收藏结构**【实，11-18—11-22 多次实测】：

| 指标 | 真实值 |
| --- | --- |
| 收藏条数 | **9 条**，1 个收藏夹 |
| 分类分布 | 工具与环境 4（44%）· 工程与方法 2（22%）· 资讯与生态 1 · 认知与判断 1 · 未归类 1 |
| **上手型占比** | **前两类合计 6/9 = 67%**（装环境、跟教程、跟着做一遍） |
| 收藏跨度 | 2023-11-03 → 2025-12-20，**778 天，但只集中在 6 天** |
| 关注的用户 | **3 个**（工程与方法 / 资讯与生态 / 职业与行业，各类各 1 条） |
| 创作内容 | **1 条**（论证结构偏「痛点式」，与「步骤式」同分 → **弱结论，不夸大**） |

**这个结构的含义**：收藏不是知识储备，是**任务驱动的临时抓取**——一遇任务就只抓「怎么立刻上手」，任务结束就再也不碰。**收藏夹里的东西没有变成能力，只是变成了垃圾。**

### 3.2 产品把「断层」显性化

桌宠的「照镜子」环节会把两件事并排放：**你说的**（自述问卷）vs **做的**（收藏/关注/创作的真实行为），然后给出断层。

【实】断层面板实测输出：

> 「你说你重「长期主义」，但你收藏的 **67%（6/9 条）**是「怎么立刻上手」——装环境、跟教程、跟着做一遍。」

强度 0.67 / 置信度 0.6 / 3 个信号 / 4 条证据。证据栏同时写明不确定性：「收藏跨度 778 天但只集中在 6 天，是任务驱动型收藏——所以这个结论对**「你在任务里怎么做事」**解释力强，对「你平时怎么想」解释力弱。」

**诚实底线**：断层必须**至少 2 个独立可用信号**才成立；不够时界面直接显示「信号不够，断层不成立」，桌宠台词是「这次信号不够我下判断——先不照了」【实，11-19 用户拍板排进脚本】。

### 3.3 知乎生态内的实际价值

- **对提问者**：「问题发现」把用户的主题接上知乎正在被问的问题 → 提问有人答，回答有人看。
- **对答题者**：用户带真实场景来提问，答案更可能落地成经验而不是通用科普。
- **对社区**：「从心」不消费知乎、**不刷屏、不批量灌水**（官方调用规范红线），只做**低频、点对点、带出处的引用**。它让知乎的存量回答在**别人的真实任务里被重新用上**。

## 四、与知乎社区生态的契合度

### 4.1 逐条对接官方开放能力

| 官方能力 | 我们用它做什么 | 实测结果 |
| --- | --- | --- |
| **问题发现**（100 次/天） | 找主题下知乎正在被问的问题 → 出题、找观点卡 | 【实】主路径；一次完整演练只烧 **6 次**（同题两答 + 5 分钟缓存省掉了） |
| **问题回答摘要**（100 次/天） | 取真实回答摘要 + **原始回答链接** → 卡片带出处 | 【实】上游返回 `Url` 字段，可直接回跳 `zhihu.com` |
| **知乎用户数据**（10000 次/天） | 读收藏夹 / 关注 / 创作 → 行为对照三信号 | 【实】9 条收藏 / 3 个关注 / 1 条创作 |
| **直答 Agent**（100 次/天） | 只做情境题的**题面改写**与快速解释 | 【实】上游 `zhida-fast-1p5`；**题面出处来自上游，模型不给出处** |
| **知乎搜索 / 全网搜索 / 热榜** | 备用与扩展，热榜**首版不做**（主线关联弱） | 【实】额度与官网标称一致 |

### 4.2 官方口径的三处背书

1. **赛道**：官方赛道二原文写着「**AI 学习伙伴、情绪陪伴型 Agent、桌面数字助手**」「**数字桌宠类创意原型**」，并配刘看山 IP 全套素材「鼓励融入作品」。【实】方向有官方原文背书。
2. **角色**：桌宠主体用**知乎官方 IP 刘看山**，官方 6 个动作与应用状态一一映射（其中「电波」= 坐着看电脑 + 灯泡，正好对应「去知乎检索」这个核心动作）。素材仅本届比赛期间可用，赛后不得商用。
3. **部署**：官方 FAQ 原文「前端 + Node 后端且不含数据库写入的全栈项目 → 可用知乎 AiWorks 提供的部署能力」——「从心」的技术底座正好命中。

### 4.3 我们**没有**依赖的东西（诚实起见）

- **不依赖看山工作台**：官方 FAQ「不限制 Agent 开发工具」→ 作品不要求跑在看山工作台上。
- **800 美元不是 API 额度**：那是**看山积分**（工作台内模型算力），与开放平台调用额度无关，本项目不依赖它。
- **没有自建知识图谱 / 没有多 Agent 编排 / 没有微服务**：见 §5.5 的取舍表。

## 五、技术实现方案

### 5.1 总体形态

```
浏览器（零依赖、零构建、零 npm 包）
   │  fetch → /api/*
   ▼
Node 后端（ESM，单进程，同进程挂载 /web/ 与 /assets/）
   │  鉴权 → 退避重试 → 限流 → TTL 缓存 → 请求去重
   ▼
知乎开放平台 HTTP API（developer.zhihu.com）
```

**一个进程 = 完整作品**：`npm install && npm start` 起一个进程，同时提供前端页面、素材和 14 个 API。**零数据库、零 Redis、零消息队列**，会话用进程内 `Map` + `AsyncLocalStorage`。

### 5.2 接口契约先冻结，再写代码

`contracts/api.json` = **OpenAPI 3.1**，**v0.6 / 14 个路径**，在写实现之前就冻结并交给队友并行开工（队友据此起 mock）。

- 行为读取：`/api/behavior/favorites` `/followees` `/contents`
- 认知闭环：`POST /api/behavior/tension` `POST /api/situation/question` `GET /api/terrain` `POST /api/terrain/answer`
- 卡片：`POST /api/cards`（支持 `same_question=true` → 同一问题下的两条真实回答）
- 语气：`GET /api/tone`（**14 句台词 × 2 个语气**，前端不自己抄一份）
- 登录：`/api/auth/profile` `/login` `/callback` `/logout`
- 其他：`/api/health` `/api/quota`

契约里有三条**硬规则**，自检脚本会逐条校验，改坏了会被拦下：

1. **出处必填**——卡片没有原文出处就不算卡片。
2. **空数据 ≠ 失败**——真的没数据要说「没有」，不能报「失败」；失败要说真话。
3. **断层诚实底线**——至少 2 个独立可用信号才成立。

### 5.3 失败语义是真的（对应官方检查第 7 条）

| 情况 | 返回 | 前端显示 |
| --- | --- | --- |
| 额度耗尽（上游 `Code=30002`） | **429** `ZHIHU_QUOTA_EXHAUSTED` | 「今天的调用次数用完了，明天再来」（`retryable: false`） |
| 凭据失效（上游 `Code=20001`） | 401 `ZHIHU_AUTH_INVALID` | 真实失败原因，**不回退成假数据** |
| 请求格式坏 | **400** `VALIDATION_ERROR` | 「请求格式不对，检查一下发过来的内容」 |
| 上游挂掉 | 5xx + 契约信封 | 桌宠**自己开口**说后端的 `user_hint` + 小字注错误码 |
| 收藏接口失败（首屏） | 200 + 空态 | **照常印一份报**，如实说「知乎凭据没配好或已失效，这次读不到知乎上的数据。」，**不留白、不编数字** |
| 信号不足 | 200 | 「信号不够，断层不成立。」 |

【实】以上六种失败场景全部实测通过（11-19、11-22）。

### 5.4 密钥处理（对应官方检查第 6 条）

- 密钥**只从服务端读**，四级来源：环境变量 → 环境变量指的文件 → 约定路径（`secrets/access_secret` 等 4 处）。
- **源码、前端响应、日志、截图、视频里都没有密钥**。本机开发密钥存在仓库外（`~/.zhihu-cli/access_secret`，已被 gitignore）；部署用**专门申请的部署专用密钥**，赛后删除。
- 缺密钥时后端**不退出进程**（否则评委打开链接是一片空白），而是照常启动、相关接口回真实错误提示。
- 自检脚本第 4 项用 `git ls-files --cached --others --exclude-standard` 扫描（含未跟踪的新文件），【实】本次扫描 146 个文件零命中。

### 5.5 关键取舍（我们主动砍掉了什么）

| 砍掉 | 理由 |
| --- | --- |
| 多宠物生态 / 多 Agent 团队 / 老板视角 | 没有真实任务需要不同能力并行，反而增加配置与监工成本 |
| 个人数字分身 / 长期记忆 | 比赛期内无法证明「越用越准」 |
| 知识图谱 / Neo4j / 自动双向链接 | 「把资料连起来」只证明资料被连接了，不证明用户能理解和回忆 |
| Kafka / Redis / K8s / 微服务 | 官方部署口径明确劝退多中间件方案 |
| Pixi.js 骨骼动画 / Matter.js 物理 / 力导向图布局 | 人时预算下要 2—3 天，SVG + CSS 方案约 1 天且演示效果足够 |
| 热榜 | 主线关联弱 |

### 5.6 两个 AI 平台、一份 Git 历史（创作佐证）

项目由**两个不同的 AI 开发平台、两个人**协作完成，共用一份 Git 历史。上下文分四层：**L0 契约**（`contracts/`）→ **L1 身份**（`AGENTS.md` 唯一真源，五个平台文件只做指针）→ **L2 决策**（`docs/decisions.md` D1—D55 + `docs/adr/`）→ **L3 交接**（`docs/handoffs/` 共 20 份）。配套开工 / 交接 / 交叉评审 / 提交四份协议，**13 项契约自检在每次提交前自动跑**（本次 PASS 13 / WARN 0 / FAIL 0）。

官方明确建议「保留 AI 交互记录、设计底稿和开发日志」——这套机制刚好覆盖这三样，**Git 提交历史本身就是可核查的创作佐证**。

## 六、后续落地设想

### 6.1 赛后三个月内能落地的

1. **OAuth 接入后按用户读自己的数据**：收藏 / 关注 / 创作都变成「你自己的」，而不是「这个账号的」。登录人数**直接计入最佳社区人气奖**的产出。OAuth 模块已实现（4 个 auth 路径 + 会话隔离），**12-05 拿到 App ID / App Key 后即可联调**；**Demo 主路径不依赖 OAuth**（已用真实进程验过：没有登录态时行为接口照样读得到真实收藏）。
2. **「断层」做成可积累的学习轨迹**：现在断层只对当前收藏快照成立；接上 OAuth 之后，可以看同一个人的断层随时间怎么变——**这才是「越用越准」能被证明的形态**。
3. **从单题到主题**：现在出题按收藏主题；下一步做「你这半年的收藏，反映出你在哪几个方向上有系统性投入」。

### 6.2 更大的设想（不承诺）

- **桌宠作为长期搭子**：从「一个作品」变成「一个常驻角色」——记住你的学习节奏，主动提醒你「上次那篇讲 RAG 评估的，你读完了吗」。
- **多桌宠 / 专家人格**：队友原始提案里的方向，本期明确**不做**（见 §5.5），但形态上留了口子——状态机与素材解耦，换素材不改业务代码。

### 6.3 明确不做的（边界感也是完成度）

多宠物生态、多 Agent 编排、知识图谱引擎、云原生沙箱删除文件、微服务拆分——**理由见 §5.5**，写在这里是为了让评审知道这些不是忘了做。

## 附：可粘贴进 AI Works「项目说明」字段的精简版

> 评委在平台上点开项目，先看到的是这段。建议控制在 600—900 字，保留四段结构：**做什么 / 为什么是它 / 怎么做的 / 有什么证据**。

**「从心」是一只住在桌面上的知乎学习搭子。** 它把你收藏夹里吃不完的东西嚼成每张都能点回知乎原话的知识卡片；你追问，它去知乎把同一个问题下真实存在的两条回答摆在你面前——它不替你选；它还会当场「照镜子」，把你说的和做的之间的断层指给你看。

**为什么是它。** 上届一等奖 MeetMind 把收藏变成一门课；而我们做的是一只会跟你较劲的桌宠——它给的是知乎上真实存在的分歧，不是整理好的知识产品。官方 CLI 文档明说「观点比较不要用直答替代搜索」，所以我们的主路径固定为「问题发现 → 问题回答摘要」，因为后者直接返回**原回答链接**——**能点回原文的卡片才算数**。

**怎么做。** 前端 + Node 后端单进程，零数据库零中间件，正面命中官方 AI Works 部署口径。API 契约先冻结（OpenAPI 3.1 / 14 个路径）再写实现。失败语义是真的：额度耗尽回 429「今天的调用次数用完了，明天再来」，信号不足时桌宠明说「这次信号不够我下判断」，**不返回任何伪造的兜底数据**。密钥只从服务端读，不进源码、日志、截图与视频。

**证据。** 【实】真实收藏 9 条：67%（6/9）是「怎么立刻上手」，跨度 778 天却只集中在 6 天；断层实测 3 个信号 / 强度 0.67 / 4 条证据；同题两答是同一 `question_url` 下的两条不同 `answer_url`；HTTP 回归 15/15、全自动演练 10/10 全过，**全程真实知乎数据、无 mock**。两个 AI 平台 + 两个人共用一份 Git 历史，55 条决策与 20 份交接文档本身就是创作佐证。
