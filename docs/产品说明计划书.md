## 一、一句话

> **「从心」是一只住在你桌面上的知乎学习搭子。**
> 它把你收藏夹里吃不完的东西嚼成**每张都能点回知乎原话**的知识卡片；
> 你追问「知乎上大家怎么说」，它去把**同一个问题下真实存在的两条回答**摆到你面前——**它不替你选**；
> 你也可以直接**抛一件正困扰着你的事**给它——它去知乎上找**遇到过同样问题的人**怎么处理的，
> 判断那些办法**适不适合你这个具体情况**，最后给你一个**能照着做**的方案，**每一步都能点回知乎原文**。

- **作品名 / 队名**：从心
- **赛道**：**AI × 陪伴与交互**（官方 `project_tracks` value = 8）
- **形态**：Web 应用（前端 + Node 后端，单进程，零数据库零中间件）
- **仓库**：<https://github.com/nineanswerer/congxin>
- **可运行体验链接**：【待】正式公网链接（AI Works 审核通过后生成）——**全文唯一还空着的必填项**

## 二、核心创作思路

### 2.1 桌宠是交互主体，知识卡片是它的产出物

产品的主次关系是刻意定下来的：**桌宠是交互主体**（有人格、有情绪、有反馈），**知识卡片是它的产出物**，**知乎开放能力是它的信息来源**。

这不是审美偏好，是被上届的获奖形态逼出来的决定：S2 一等奖 **MeetMind学脉**（清华，¥30,000）做的是「把收藏夹里的文章变成口播 + 板书，转为一对一老师式互动学习课程」——**「收藏夹 → 学习内容」这条路已经被占住了**。如果「从心」也做成「更聪明的卡片生成器 + 一个宠物皮肤」，评审的第一反应会是「这是 MeetMind 的降级版」，创新度（初审占 25%）会直接失分。

所以「从心」反过来做：**不是「更好用的收藏夹」，而是「一只陪你干活、并且会跟你较劲的桌宠」**。

### 2.2 一句话说清我们和上届的差别（创新度 25% 的落点）

> ✅ **这句已定稿**（2026-11-24，D66 换主线后重写，用户拍板「计划书可以定稿」）。

> **MeetMind 把你的收藏变成一门课。「从心」把你的收藏变成一个会跟你吵一架、还会跑去知乎找经历过同样困境的人问「他们怎么办」的桌宠——它给的是知乎上真实存在的分歧和能照着做的办法，不是整理好的知识产品。**

展开成三件具体的事：

| # | 差异点 | 别人（典型知识整理工具 / 上届形态） | 从心 |
| --- | --- | --- | --- |
| 1 | **有出处的观点对照** | 给 AI 写的摘要 / 结构化知识点，出处是「参考来源 1、2、3」这种模糊指向 | 给**知乎上真实存在的不同答案及其原始回答链接**，用户看到的是分歧本身；**无法回跳原文的卡片不算数** |
| 2 | **从「读到」到「能照着做」** | 工具停在「读」这一步：给你一篇讲焦虑管理的文章 | **你抛一件正困扰着你的事 → 它去知乎找遇到过同样问题的人 → 判断那套办法适不适合你这个具体情况 → 给一个能照着做的方案，每一步都标着「依据第几条」**。**出处三件套一个字段都不由模型生成**（模型只回编号，后端映射回真实 URL）→ **模型编不出出处** |
| 3 | **陪伴而非工具** | 界面是一张表单，失败了就弹 toast | 桌宠对状态有反应：咀嚼、电波检索、打盹；**找不到能对得上的办法时它会明说「这次没找到能对得上的，我不给你一个查无出处的答案」**，而不是编一个像样的建议 |

### 2.3 为什么值得用知乎的开放能力（而不是一个通用 LLM 就够了）

**观点比较这条线，我们故意不用直答 Agent。** 官方 CLI 文档原话：

> 「搜索用于取得原始资料，直答用于快速获得总结，**深度研究、事实核查和观点比较不要用直答替代搜索**。」

因此**卡片主路径**固定为 `问题发现（question_recommendations）` → `问题回答摘要（question_answers）`：后者直接返回**原回答链接**（上游响应里的 `Url` 字段），这正是「每张卡片能点回知乎原话」的技术基础。**直答只做快速解释与兜底**——这是方法论选择，不是额度问题。

官方能力表里对「问题发现」的定位原文就是「**观点对照**」，与我们的差异点 1 逐字对上。

### 2.4 新主线「问它」怎么用知乎的开放能力（**不违反上面那条**）

「问它」这条链路的分工非常清楚，**不混**：

| 环节 | 用哪个上游 | 出处从哪来 |
| --- | --- | --- |
| ① 找**相似的困境** | **知乎搜索**（`content/zhihu_search`，5000 次/天）—— 取前 6 条**真实回答** | 上游返回的 `Url` **就是原回答链接** |
| ② 判断适不适用 + 给方案 | **直答** `zhida-thinking-1p5`（100 次/天）—— 它读的是这 6 条真实回答 | **模型只回编号**，不产出任何 URL |
| ③ 把编号映射回出处 | 后端映射，**一个字段都不由模型生成** | 问题标题 / 问题 URL / 原回答 URL **全部来自上游** |

**所以我们没有「用直答替代搜索」**：事实、原文、出处**全部来自知乎搜索**；
直答只负责**在给定材料上做判断和改写成方案**——这正是官方文档说的「直答用于快速获得总结」。
**模型不可能编造出处**，因为它从来看不到 URL、只被允许回编号。

【实】**11-24 当天两次实跑**（同一份部署包，真调知乎）：

| 问什么 | 判断 | 候选 | 方案步数 | 出处条数 |
| --- | --- | ---: | ---: | ---: |
| 工作压力大到睡不着怎么办 | `applicable`（这些办法对你适用） | 6 | 5 步 | 5 条 |
| 我总是拖到 deadline 才动手，明知来不及还是先刷手机 | `partially_applicable`（部分适用 —— 挑着看） | 6 | 4 步 | 5 条 |

点开每一条出处都是 `zhihu.com/question/.../answer/...` 或 `zhuanlan.zhihu.com/p/...`，**真实原回答链接**。

> **步数与条数每次实跑会变**（模型给的方案长度不同）——**但形状固定**：
> 判断（三档）→ 一句话结论 → N 步方案（每步带「依据 N 条」）→ M 条真实出处。
> 回归脚本第 11—13 拍就是按这个形状断言的，不按具体数字。

## 三、场景价值

### 3.1 痛点（真实，不是想出来的）

用户自己写在知乎创作里的原话【实，11-19 实测取出】：

> **「我的收藏夹里有 200 篇 PDF，一篇都没用上。」**

这不是个别现象。我们账号的**真实收藏结构**【实，11-18—11-22 多次实测】：

| 指标 | 真实值 |
| --- | --- |
| 收藏条数 | **9 条**，1 个收藏夹 |
| 分类分布 | 工具与环境 4（44%）· 工程与方法 2（22%）· 资讯与生态 1 · 认知与判断 1 · 未归类 1 |
| **上手型占比** | **前两类合计 6/9 = 67%**（装环境、跟教程、跟着做一遍） |
| 收藏跨度 | 2023-11-03 → 2025-12-20，**778 天，但只集中在 6 天** |
| 关注的用户 | **3 个**（工程与方法 / 资讯与生态 / 职业与行业，各类各 1 条） |
| 创作内容 | **1 条**（论证结构偏「痛点式」，与「步骤式」同分 → **弱结论，不夸大**） |

**这个结构的含义**：收藏不是知识储备，是**任务驱动的临时抓取**——一遇任务就只抓「怎么立刻上手」，任务结束就再也不碰。**收藏夹里的东西没有变成能力，只是变成了垃圾。**

### 3.2 产品把「别人的经验」变成「你今晚就能做的几步」

收藏里那些内容（装环境、跟教程、跟着做一遍）证明的是**别人怎么做事**，不是**你眼下该怎么办**。
「问它」补的就是这一段：**你把正困扰着你的那件事说出来 → 它去知乎上找遇到过同样问题的人**
→ 从那些真实回答里判断**这些办法适不适合你这个具体情况** → 最后给一个**能照着做**的方案。

【实】11-24 实测（问「工作压力大到睡不着怎么办」，当次跑出的 6 步方案）——判断「这些办法对你适用」+ 一句话结论 + **6 步方案**，每一步都标着依据：

| 步骤 | 依据 |
| --- | --- |
| 睡前花 5 分钟把明天待办、要回复的人和担心的事全部写下来，并告诉自己「今天能做的已经做完了」 | 依据 2、6 条 |
| 下班后留出约 30 分钟缓冲，散步、洗热水澡、看纸质书或做放松练习 | 依据 5 条 |
| 固定起床和睡觉时间，不在床上工作、回消息或刷手机 | 依据 1、6 条 |
| 躺下后做渐进式肌肉放松或身体扫描 | 依据 2、5 条 |
| 白天安排散步等规律运动，下午之后不喝咖啡、奶茶 | 依据 1 条 |
| 焦虑冒出来时，不急着消灭它，只说「我注意到自己现在有些紧张」 | 依据 6 条 |

**边界也如实说**：材料只提到「严重或持续失眠需要专业帮助」，它就照实写「严重或持续失眠还需要专业帮助」——
**不越过材料给建议**。

【实】同日另一次实跑（问「我总是拖到 deadline 才动手，明知来不及还是先刷手机」）——判断**「部分适用 —— 挑着看」**，
给 **4 步方案** + **5 条真实出处**，其中一条是知乎专栏（`zhuanlan.zhihu.com/p/...`，作者的原始回答）：

| 步骤 | 依据 |
| --- | --- |
| 选一个最小动作只做 5 分钟，比如打开文档写一行或读一页，告诉自己「不用做完，只做 5 分钟」 | 依据 2、3、6 条 |
| 工作学习时把手机静音、放到视线外，关闭推荐，桌面只留当前任务 | 依据 6 条 |
| 给任务设一个比真实 deadline 更早的硬截止时间，例如「今晚 8 点前先完成第一小段」 | 依据 6 条 |
| 开始前若感到烦躁或怕做不好，先写下「我现在在逃避哪种感受」，不自责，然后回到 5 分钟动作 | 依据 1、5 条 |

> **它也会说「不适用的部分」**：判断是三档而不是二选一（`applicable` / `partially_applicable` / `not_applicable`），
> `partially_applicable` 时界面直接写「部分适用 —— 挑着看」，**不把「有一半能用」说成「能用」**。
> **这正是静帧 2 画的那一屏**（`docs/p1-frames/frame-2-ask.png`）。

**诚实底线（三条，都写在代码与契约里，自检会逐条校验）**：

1. **出处必填**——每一步的依据编号都必须能在出处列表里找得到；**没有对得上出处的建议不给**。
2. **空数据 ≠ 失败**——知乎上搜不到，就说「知乎上暂时没搜到跟这个问题相关的内容」，不编。
3. **失败必须是真话**——直答没给出可核对的引用 → **不给方案**，只说「这次没能把建议对上知乎原文出处」。

### 3.3 知乎生态内的实际价值

- **对提问者**：「问题发现」把用户的主题接上知乎正在被问的问题 → 提问有人答，回答有人看。
- **对答题者**：用户带真实场景来提问，答案更可能落地成经验而不是通用科普。
- **对社区**：「从心」不消费知乎、**不刷屏、不批量灌水**（官方调用规范红线），只做**低频、点对点、带出处的引用**。它让知乎的存量回答在**别人的真实任务里被重新用上**。

## 四、与知乎社区生态的契合度

### 4.1 逐条对接官方开放能力

| 官方能力 | 我们用它做什么 | 实测结果 |
| --- | --- | --- |
| **问题发现**（100 次/天） | 找主题下知乎正在被问的问题 → 出观点卡 | 【实】卡片主路径；一次完整演练只烧 **6 次**（同题两答 + 5 分钟缓存省掉了） |
| **问题回答摘要**（100 次/天） | 取真实回答摘要 + **原始回答链接** → 卡片带出处 | 【实】上游返回 `Url` 字段，可直接回跳 `zhihu.com` |
| **知乎搜索**（5000 次/天） | **「问它」新主线的上游**：按你的问题找**相似的困境**，取前 6 条真实回答 | 【实】11-24 实测：返回 `Answer` 类型，**`Url` 就是原回答链接**（`/question/<qid>/answer/<aid>`）→ 出处三件套能全推出来 |
| **知乎用户数据**（10000 次/天） | 读收藏夹 / 关注 / 创作 → 首屏真实收藏与日报 | 【实】9 条收藏 / 3 个关注 / 1 条创作 |
| **直答 Agent**（100 次/天） | **「问它」的判断与方案**：读上面那 6 条真实回答 → 判断适不适用 + 给方案 | 【实】上游 `zhida-thinking-1p5`；**模型只回编号，出处一个字段都不由它生成** |
| **全网搜索 / 热榜** | 备用与扩展，热榜**首版不做**（主线关联弱） | 【实】额度与官网标称一致 |

### 4.2 官方口径的三处背书

1. **赛道**：官方赛道二原文写着「**AI 学习伙伴、情绪陪伴型 Agent、桌面数字助手**」「**数字桌宠类创意原型**」，并配刘看山 IP 全套素材「鼓励融入作品」。【实】方向有官方原文背书。
2. **角色**：桌宠主体用**知乎官方 IP 刘看山**，官方 6 个动作与应用状态一一映射（其中「电波」= 坐着看电脑 + 灯泡，正好对应「去知乎检索」这个核心动作）。素材仅本届比赛期间可用，赛后不得商用。
3. **部署**：官方 FAQ 原文「前端 + Node 后端且不含数据库写入的全栈项目 → 可用知乎 AiWorks 提供的部署能力」——「从心」的技术底座正好命中。

### 4.3 我们**没有**依赖的东西（诚实起见）

- **不依赖看山工作台**：官方 FAQ「不限制 Agent 开发工具」→ 作品不要求跑在看山工作台上。
- **800 美元不是 API 额度**：那是**看山积分**（工作台内模型算力），与开放平台调用额度无关，本项目不依赖它。
- **没有自建知识图谱 / 没有多 Agent 编排 / 没有微服务**：见 §5.5 的取舍表。

## 五、技术实现方案

### 5.1 总体形态

```
浏览器（零依赖、零构建、零 npm 包）
   │  fetch → /api/*
   ▼
Node 后端（ESM，单进程，同进程挂载 /web/ 与 /assets/）
   │  鉴权 → 退避重试 → 限流 → TTL 缓存 → 请求去重
   ▼
知乎开放平台 HTTP API（developer.zhihu.com）
```

**一个进程 = 完整作品**：`npm install && npm start` 起一个进程，同时提供前端页面、素材和 **11 个 API**。**零数据库、零 Redis、零消息队列**，会话用进程内 `Map` + `AsyncLocalStorage`。

### 5.2 接口契约先冻结，再写代码

`contracts/api.json` = **OpenAPI 3.1**，**v0.7 / 11 个路径**（D66：删掉 4 个认知闭环路径，加 `POST /api/advice`）。

- 行为读取：`/api/behavior/favorites` `/followees` `/contents`
- 卡片：`POST /api/cards`（支持 `same_question=true` → 同一问题下的两条真实回答）
- **「问它」：`POST /api/advice`**（`{question, tone?}` → 判断 + 一句话结论 + 方案步骤 + 出处三件套）
- 语气：`GET /api/tone`（**14 句台词 × 2 个语气**，前端不自己抄一份）
- 登录：`/api/auth/profile` `/login` `/callback` `/logout`
- 其他：`/api/health` `/api/quota`

契约里有三条**硬规则**，自检脚本会逐条校验，改坏了会被拦下：

1. **出处必填**——卡片没有原文出处就不算卡片；「问它」的每一步依据编号必须能在出处列表里找到。
2. **空数据 ≠ 失败**——真的没数据要说「没有」，不能报「失败」；失败要说真话。
3. **没对得上出处就不给方案**——直答给不出可核对的引用 → **不给方案**，只说真话。

### 5.3 失败语义是真的（对应官方检查第 7 条）

| 情况 | 返回 | 前端显示 |
| --- | --- | --- |

### 5.4 密钥处理（对应官方检查第 6 条）

- 密钥**只从服务端读**，四级来源：环境变量 → 环境变量指的文件 → 约定路径（`secrets/access_secret` 等 4 处）。
- **源码、前端响应、日志、截图、视频里都没有密钥**。本机开发密钥存在仓库外（`~/.zhihu-cli/access_secret`，已被 gitignore）；部署用**专门申请的部署专用密钥**，赛后删除。
- 缺密钥时后端**不退出进程**（否则评委打开链接是一片空白），而是照常启动、相关接口回真实错误提示。
- 自检脚本第 4 项用 `git ls-files --cached --others --exclude-standard` 扫描（含未跟踪的新文件），【实】本次扫描 **1767 个文件零命中**。

### 5.7 新主线「问它」的实现要点

> 【实】11-24 已实现并实跑通过（`server/src/services/advice.js` + `POST /api/advice`）。

- **链路四步**：① 知乎搜索（`content/zhihu_search`，**5000 次/天**）按你的问题搜 → ② 取前 **6** 条候选（正文截 **700** 字）
  → ③ 直答 `zhida-thinking-1p5` 判断**适不适用** + 给方案 → ④ 后端把模型回的**编号**映射回**上游真实 URL**。
- **出处三件套一个字段都不由模型生成**（问题标题 / 问题 URL / 原回答 URL 全部来自上游）→ **模型不可能编造出处**。
- **提示词踩过的坑（别改回去）**：格式要求**必须和材料一起写在 `user` 消息里** —— 放 `system` 里要求「只输出 JSON」，
  `zhida-thinking-1p5` 会**完全无视**并返回一篇 786 字长文；**格式 + 材料一起进 `user` → 一次就完美听话**。
  （`zhida-thinking-1p5` 与 `zhida-fast-1p5` 都不认 `response_format`。）
- **两级缓存各 5 分钟**：搜索结果与完整结果分开缓存 → **同一个问题重复问不再烧直答额度**（演示要反复问同一个问题）。
- **失败是真话**：模型给不出可核对的引用 → **不给方案**，只说「这次没能把建议对上知乎原文出处」。
- 【实】实测：问「工作压力大到睡不着怎么办」→ 判断 `applicable` + 一句话结论 + **6 步方案** + **4 条真实出处**
  （含 `zhihu.com/question/.../answer/...` 与 `zhuanlan.zhihu.com/p/...`）；再问一次命中缓存。

## 六、后续落地设想

### 6.1 赛后三个月内能落地的

1. **OAuth 接入后按用户读自己的数据**：收藏 / 关注 / 创作都变成「你自己的」，而不是「这个账号的」。登录人数**直接计入最佳社区人气奖**的产出。OAuth 模块已实现（4 个 auth 路径 + 会话隔离），**12-05 拿到 App ID / App Key 后即可联调**；**Demo 主路径不依赖 OAuth**（已用真实进程验过：没有登录态时行为接口照样读得到真实收藏）。
2. **「问它」做成可积累的求助记录**：现在每次问都是一次性的；接上 OAuth 之后，可以看**同一个人的困境和办法随时间怎么变**——比如「你上次也是工作压力睡不着，那次用的办法有没有用」。**这才是「越用越准」能被证明的形态**。
3. **从单题到主题**：现在按你当场说的一件事搜；下一步做「你这半年的收藏，反映出你在哪几个方向上反复卡住」。

### 6.2 更大的设想（不承诺）

- **桌宠作为长期搭子**：从「一个作品」变成「一个常驻角色」——记住你的学习节奏，主动提醒你「上次那篇讲 RAG 评估的，你读完了吗」。
- **多桌宠 / 专家人格**：队友原始提案里的方向，本期明确**不做**（见 §5.5），但形态上留了口子——状态机与素材解耦，换素材不改业务代码。

### 6.3 明确不做的（边界感也是完成度）

多宠物生态、多 Agent 编排、知识图谱引擎、云原生沙箱删除文件、微服务拆分——**理由见 §5.5**，写在这里是为了让评审知道这些不是忘了做。

## 附：可粘贴进 AI Works「项目说明」字段的精简版

> 评委在平台上点开项目，先看到的是这段。建议控制在 600—900 字，保留四段结构：**做什么 / 为什么是它 / 怎么做的 / 有什么证据**。

**「从心」是一只住在桌面上的知乎学习搭子。** 它把你收藏夹里吃不完的东西嚼成每张都能点回知乎原话的知识卡片；你追问，它去知乎把同一个问题下真实存在的两条回答摆到你面前——它不替你选。你也可以直接把正困扰着你的那件事抛给它：它去知乎上找遇到过同样问题的人，判断那些办法适不适合你这个具体情况，给你一个能照着做的方案，每一步都标着依据。

**为什么是它。** 上届一等奖 MeetMind 把收藏变成一门课；而我们做的是一只会跟你较劲的桌宠——它给的是知乎上真实存在的分歧和能照着做的办法，不是整理好的知识产品。官方 CLI 文档明说「观点比较不要用直答替代搜索」，所以卡片主路径固定为「问题发现 → 问题回答摘要」；而「问它」这条线上**事实与出处全部来自知乎搜索**，直答只在给定材料上做判断和改写成方案，**出处三件套一个字段都不由模型生成**——**模型编不出出处**。

**怎么做。** 前端 + Node 后端单进程，零数据库零中间件，正面命中官方 AI Works 部署口径。API 契约先冻结（OpenAPI 3.1 / 11 个路径）再写实现。失败语义是真的：额度耗尽回 429「今天的调用次数用完了，明天再来」；搜不到或对不上出处时，桌宠明说「我不给你一个查无出处的答案」，**不返回任何伪造的兜底数据**。密钥只从服务端读，不进源码、日志、截图与视频。
