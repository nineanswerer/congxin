## 七、部署

官方 FAQ 原文口径：

- **架构复杂、多中间件（Redis、MySQL、消息队列等）** → 推荐云主机部署，便于灵活配置环境。
- **常规项目** → 推荐 [CloudBase](https://tcb.cloud.tencent.com/) 等一站式部署平台，开箱即用免运维。
- **前端 + Node 后端且不含数据库写入的全栈项目** → 可用知乎 [AiWorks](https://www.zhihu.com/project-square) 提供的部署能力。

OAuth 相关（官方 FAQ）：

- OAuth 登录是相对独立的模块，**可以先把项目跑通再接入**。
- 账号需满足**实名制、有手机号、实名认证**，才能通过 OAuth 校验。
- 调用 `/authorize` 时 `redirect_uri` 必须与 App 指定的回调地址**完全一致**（含协议、域名、参数）。
- 在黑客松项目中拿到 App ID 和 OAuth App Key、配置回调地址后，可直接把现有项目交给 Agent 完成接入。

### 12.3 OAuth 凭证的领取时机（解决了此前的疑问）

- App ID 与 App Key 在**项目创建后**由赛事页面分配，**不走通用邮件申请流程**。
- 开发期可先完成代码、配置模板与 Mock 测试；**尚无凭证时不要编造提前领取入口**。
- **只做知乎登录 + 取基础信息，不需要 Access Secret**：`GET https://openapi.zhihu.com/user`，`Authorization: Bearer <OAuth access_token>`。
- 读授权用户的创作列表、关注、收藏时，才需要 `Authorization: Bearer <Access Secret>` + `X-OAuth-Token` + `X-Request-Timestamp`。
- 纯浏览器项目需增加最小后端负责 Token 交换与会话管理。**常驻单进程 Demo 可用进程内 Map 保存会话标识、Token、过期时间与用户身份**；多实例或 Serverless 才需共享会话存储。
- 浏览器只持应用自己的随机会话标识，用 `HttpOnly` + `Secure` Cookie 承载；OAuth Token 留服务端。退出或会话失效时清理映射，**Token 过期时不切换到 Access Secret 所属账号**，不自动重新登录。
- 环境变量命名：`ZHIHU_OAUTH_APP_ID` / `ZHIHU_OAUTH_APP_KEY` / `ZHIHU_OAUTH_REDIRECT_URI` / `ZHIHU_ACCESS_SECRET`。App ID 可公开，其余三个只进服务端。

### 13.2 三条由此推出的战略结论

1. **"把收藏的资料变成学习内容"这条路，上届一等奖已经占住了。** 本届若再做"收藏夹 → 课程 / 摘要 / 知识卡片"，创新度（25%）会被直接质疑"这是 MeetMind 的降级版"，计划书里"核心创新"一项会写不出来。必须做出**能一句话说清的区别**。

3. **所以定位要反过来：不是"更好用的收藏夹"，而是"有陪伴感的桌宠"。** 桌宠是**交互主体**，知识卡片是它的**产出物**；知乎能力是它的**信息来源**。这个主次关系一旦搞反，就会做成上届的形状。

## 十四、接口接入面（2026-11-16 由 zhihu-cli 0.6.3 `capabilities` 与官方 Skill 文档核对）

### 14.1 HTTP API（服务域名 `https://developer.zhihu.com`）

鉴权统一为 `Authorization: Bearer <Access Secret>` + `X-Request-Timestamp: <Unix 秒级时间戳>`。

| 能力 | HTTP 路径 | CLI 命令 | 官方 MCP |
| --- | --- | --- | --- |
| 知乎搜索 | `/api/v1/content/zhihu_search` | `search zhihu` | ✅ `zhihu_search` |
| 全网搜索 | `/api/v1/content/global_search` | `search global` | ✅ `global_search` |
| 知乎热榜 | `/api/v1/content/hot_list` | `hot` | ✅ `hot_list` |
| **知乎直答** | **`/v1/chat/completions`**（OpenAI 兼容） | `answer` | ✅ `zhida` |
| **问题回答摘要** | `/api/v1/content/question_answers` | `question answers` | ❌ **无 MCP** |
| **主题问题推荐** | `/api/v1/user/question_recommendations` | `question recommend` | ❌ **无 MCP** |
| 知识库 增删查/上传 | `/api/v1/knowledge/*` | `knowledge ...` | ❌ 无 MCP |
| 额度查询 | `/api/v1/quota` | `quota` | ❌ 无 MCP |
| 本人创作/评论/统计/关注/收藏 | `/api/v1/user/*` | `me ...` | ❌ 无 MCP |

**结论：官方 MCP 只覆盖 4 项能力，本项目主路径所需的 `question recommend` 与 `question answers` 都没有 MCP 服务。** 所以应用后端应**直接调 HTTP API**，不走 MCP。

### 14.2 直答的三档模型（`answer` 命令 / `zhida` 工具）

| 模型 | 含义 |
| --- | --- |
| `zhida-fast-1p5` | 快速回答 |
| `zhida-thinking-1p5` | 深度思考 |
| **`zhida-agent`** | **智能检索与回答** |

直答支持流式（`stream: true`，CLI 用 `--output sse`；MCP 用 Streamable HTTP），搜索与热榜不支持流式。

### 14.3 Access Secret 申请与配置

- 入口：<https://developer.zhihu.com/profile> → 知乎账号登录 → 「申请新 Access Secret」。
- 单账号最多 20 个 Access Secret；**删除后无法恢复**；同账号下所有 Access Secret 共享额度。
- 配置：`zhihu-cli auth set --secret-stdin`（CLI 会先在线验证新 Secret，再替换系统密钥链中的旧 Secret）。
- 免费额度用尽后能否付费调用，见 <https://developer.zhihu.com/docs?key=billing_price>。
- API 接入咨询：openplatform@zhihu.com。

| --- | --- | --- | --- |

**结论与影响**：

1. 官网标注的是**本届赛事专属额度**，通过官方群领取的 Token / 看山工作台发放；普通自申请的 Access Secret 只有很小的免费额度。
2. **直答 2 次/天、热榜 2 次/天**意味着：靠普通额度做现场 Demo 几乎不可行。**演示前必须拿到赛事专属额度**——加官方助手进官方群领 Token 是当前优先级最高的对外动作。
3. 官方开发文档明确要求"调用开放能力时**做好缓存和请求去重**"。在本届不是最佳实践，是**生死线**：必须做请求缓存、额度实时查询、额度耗尽的真实提示。
4. 演示策略：热门路径做**预生成缓存**，现场命中缓存；缓存未命中且额度耗尽时给真实提示，**绝不返回伪造数据**（对应官方提交检查第 7 条）。
5. 同账号下所有 Access Secret 共享额度；额度用尽后能否付费调用见 <https://developer.zhihu.com/docs?key=billing_price>。
