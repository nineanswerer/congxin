> ### 零 E · 回复"GitHub 提交 + 两个人用不同 AI"的疑虑（**机制已落地，照抄即可**）
>
> 那个顾虑我认真想了一遍，结论是：**两个 AI 反而是我们的优势，不是风险。**
>
> 先说为什么。官方在赛规里明确建议保留 **AI 交互记录、设计底稿和开发日志** 作为创作佐证。我们俩各用一个 AI，仓库里天然就有两条独立的开发轨迹，外加每一步"为什么这么改"的说明——**这正是评审要看的东西**。而且两个模型的盲区不一样，我可以把我的改动丢给你那个 AI 挑一遍错，它能捞出我自己看不出的问题，这是单模型做不到的。
>
> 真正的风险不是"两个 AI"，是"**换 AI 之后上下文丢了**"。Git 只记代码改成了啥，不记**为什么这么改**、**试过什么失败了**——这个坑我已经在仓库里补上了。
>
> **机制已经写进仓库了**，你打开就能看到（`docs/协作规范.md`），现在长这样：
>
> - **一份契约**（`contracts/contract.json`）——赛程时间、接口额度、技术底座、合规红线这些"改错了会让你环境静默出错"的事实，写成机器能读的文件，提交前自动核对
> - **一份规则**（`AGENTS.md`）——项目唯一的规则正文。你那边不管用 Cursor 还是 Gemini 还是别的，我这边用 MCode，**我们读的是同一份**；各平台的配置文件只做指针、不复制正文（复制了就各改各的，很快越走越偏）
> - **一份决策记录**（`docs/decisions.md` + `docs/adr/`）——每个决定连"否决了哪些方案、为什么"一起记，免得下次又讨论一遍
> - **一份交接记录**（`docs/handoffs/`）——每换一次 AI 之前，让 AI 自己写一份交接。**它刚干完活，记忆是全的**，你说出来反而容易漏
>
> **要你做的事，现在只剩两件，都是一句话的事：**
>
> 1. **跟 AI 说清"为什么改"**。就一句话，说完 AI 会转录到 `.ctx/current.md`，提交时 hook 自动填进 commit message——**你不用手改 commit message**。剩下的 `Tried:`（试过什么）和 `Verify:`（怎么验证的）AI 自己写，它确实知道。
> 2. **第一次在你自己的电脑上 clone 之后，跑一条命令**：`powershell -ExecutionPolicy Bypass -File scripts/install-hooks.ps1`（我这边已经装好了；不装的话格式检查不生效）。跑完顺手确认 `core.hooksPath = .githooks`。
>
> **换 AI 平台不用你操心了**：各平台打开仓库时会自动加载自己的规则文件，里面直接指向开工协议，新 AI 自己会读——读契约 → 复述现状 → 停下来等你确认 → 确认完才准动文件。`git pull` 之后还会自动弹一份开工清单，提醒"契约变了要重读"。**会话结束时的交接也是 AI 自己写**，不用你提醒。

> - 拿不到资料时后端会给 `empty: true` + 一句中文 `empty_notice`，**把那句显示出来就行，别自己编一个昵称**。
>
> 接口总数现在是 **13 个**（9 + 4 个登录路径）；已有那 8 个的请求体和响应体**一个字段都没改**。

## 二、D14：桌宠是主体还是皮肤（**最重要的一件**）

### 两种形态长什么样

**形态 A —— 卡片生成器为主，桌宠是皮肤**
- 用户打开看到的是一堆卡片、一套工具栏；桌宠在角落飘着，偶尔弹一句话
- **把桌宠删掉，产品几乎不变**
- 评审眼里的它：一个"AI 卡片工具"，宠物是装饰 → 创新度低

**形态 B —— 桌宠是主体，卡片是它的产出物**
- 用户打开看到的是**一只桌宠**；它"吃"下资料 → 咀嚼 → 去知乎检索 → 吐出卡片；卡片是它工作过的痕迹
- **把桌宠删掉，主流程塌了；把知乎删掉，价值塌一半**
- 评审眼里的它：一个有生命的角色在帮你学习 → 创新度高，且正对 S3 首次单列的"AI × 陪伴与交互"赛道

### 判据（一句话终结争论）

> **把知乎整个拔掉，这个产品还成立吗？**
> 还成立（只少个信息源）→ 桌宠是皮肤；**不成立** → 桌宠是主体。
> 本项目选后者：`question recommend` + `question answers` 是"卡片有出处、有分歧"的**唯一**来源，拔掉知乎就没有差异点 1 和 2。

### 差异点三连（写进计划书"核心创新"）

1. **有出处的观点对照** —— 不给 AI 黑盒摘要，给知乎上真实的不同答案**及其原始链接**，让用户看到分歧本身
2. **问题反哺** —— 桌宠指出"你这个主题，知乎上正在被问的问题"（官方对"问题发现"的能力定位原文就是"观点对照"）
3. **陪伴而非工具** —— 桌宠对状态有反应（思考 / 打盹 / 答错后的沮丧），让"整理资料"不再像 chores

### 为什么不能主次颠倒（评审角度）

- S2 一等奖 **MeetMind学脉** 已经占了"把收藏资料变成学习内容"这个位置 → 形态 A 会被读成它的降级版，创新度（25% 权重）直接失分
- S3 **首次单列**"AI × 陪伴与交互"赛道，上届无对等获奖形态 → 桌宠路线才是结构性机会；该赛道有 **最佳交互陪伴奖 ¥2,000（1 支）**
- 形态 A 会被归到"AI × 知识与探索"（01），撞车风险高

### 白皮书 9 概念的处置（谈判用这张表）

| # | 白皮书概念 | 处置 | 落到哪 |
| --- | --- | --- | --- |
| 1 | 具身化智能体 | **保留** | 桌宠作为交互主体 |
| 2 | 吞噬与知识内化 | **保留**（改实现） | 拖入 → 咀嚼 `eating` → 吐卡片 `emitting`；双向链接改为**带出处的卡片** |
| 3 | 具象化建房子 | **保留**（大幅简化） | 卡片可归置的"小屋" + 检索；**不做**自动双向链接图谱 |
| 4 | 装备与专家系统 | 砍掉 | 需要插件 Schema + 沙箱执行器 |
| 5 | 点头授权 | 砍掉 | 改为**显式确认 UI**，不用原生弹窗（原生弹窗 ≠ 安全，见 D6） |
| 6 | 多宠物生态 | 砍掉 | 首版只有一只 |
| 7 | 老板视角与多 Agent 团队 | 砍掉 | 真实任务不需要并发编排 |
| 8 | 个人数字分身 | 砍掉 | 比赛期内无法证明"越用越准" |
| 9 | 多平台与社交 / A2A | 砍掉 | 成本收益完全不成比例 |
| ＋ | **知乎作为信息来源** | **新增** | 差异点 1 / 2；也是 40% "AI 场景价值"的落点 |

**一句话版本：保留 3 个、砍掉 6 个、新增 1 个。砍掉的 6 个是与"一个具体任务里的学习搭子"无关的平台能力，不是"不要桌宠"。**

## 三、D19：角色设定（刘看山 vs 自定义宠物）

> D14 决定"**谁是主角**"，D19 决定"**主角长什么样**"。是两件事。

| 维度 | **刘看山（官方 IP）** | **自定义宠物** |
| --- | --- | --- |
| 美术成本 | **0**（官方素材已就位，WebP 优化后 6 个动作共 915 KB） | 高。38 人时预算下自制一套有生命感的动画不可能 |
| 赛道适配 | 官方赛道明确"开放刘看山官方 IP 素材" | 无额外加成 |
| 评审观感 | 评审含知乎高管与内部业务线负责人 → 用官方 IP 是**加分** | 自绘角色在决赛直播里一眼看出廉价 → 设计感（10%）失分 |
| 核心风险 | **评委可能误以为"这是官方自己做的"** → 差异化必须落在"它做的事"，不是"它是谁" | 角色不独特 / 做不出来 |
| 后续风险 | **仅本届比赛期间可用，赛后禁商用**（D20 已用"状态机与素材解耦"对冲：素材缺失降级为静态占位，业务代码不动） | 无 |
| 素材缺口 | 只有 6 个情绪动作，缺"吞咽 / 吐卡片 / 失败"三个核心瞬间 → 用 CSS 过渡 + 状态气泡补，**不自绘角色** | 自己补齐所有动作，成本更高 |

### 已核实的一个关键事实

队友白皮书**全文没有角色 / 形象 / IP 设计**（角色、形象、外观、美术、立绘、吉祥物均无命中）。所以 D19 **不是"我们的原创角色 vs 刘看山"的对立**，而只是"用官方素材 vs 从零画"。默认解很清楚：**刘看山**。

### 建议结论

**先用刘看山**，理由：素材零成本、赛道官方支持、评审加分、语义上"电波"动作（坐着看电脑 + 头顶灯泡）与"桌宠去知乎检索"高度同构，几乎不用解释就能对上。
**同时保留可替换性**（D20 已做）：状态机不认识素材，只认识 `idle / thinking / cheer / greet / sleep / play` 这几个状态 → 赛后撤 IP 或换角色都不改业务代码。

**要问队友的一句话**：白皮书里没写角色，我们默认用官方刘看山；**如果他心里有一个具体形象（比如某个原创角色），现在提出来**——那时才需要真正讨论自绘 vs 用官方，因为那代表已有沉没成本。

## 六、他一定会问的三个问题，提前备好答案

**Q：我们的知乎 API 额度够吗？**
> **够。** 账号完成**实名认证**后实测：搜索 5000 次/天、直答 100 次/天、问题发现 100 次/天、PDF 解析 10 次/天，**与官网标的完全一致**。
> （此前"黑客松专属额度"的说法是误传——真因就是实名认证；800 美元积分是工作台里的模型算力，跟接口额度无关，**也不需要再去找官方开通**。）
> 所以首版的取舍与额度无关：**不做热榜**（主线关联弱 + 预算）、**直答只兜底**（观点比较必须用能返回**原始链接**的接口）、**PDF 解析本地化**（官方 10 次/天撑不住运营期）。缓存与去重仍必做，理由是防重复计费，不是省着用。

**Q：为什么不做数据库 / 微服务？**
> 官方 FAQ：前端 + Node 后端且不含数据库写入 → 可用 AI Works 一键部署；平台**暂不支持独立数据库托管**。我们单进程进程内 Map 存会话，零中间件，部署最快、故障面最小。

**Q：为什么不是 Tauri 桌面端？**
> OAuth 登录人数和人气奖只对 Web 友好；19 天做桌面端不现实。PWA 能做到独立窗口 + 图标 + 桌宠悬浮层，够用。
