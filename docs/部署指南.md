## 1. 先在本地跑一次预检（一条命令）

```powershell
cd 'C:\Users\steam\Desktop\从心'
node scripts\predeploy-check.js
```

它会做六件事：

1. 检查源码树的部署面（必需文件、契约、挂载顺序、密钥读取方式）
2. 打包成 ZIP（**白名单**，不含 `node_modules/` `.git/` `.ctx/` `docs/` `.env*` `access_secret` `secrets/`）
3. **把 ZIP 解到临时目录**（模拟平台拿到包的样子）
4. 对**解包结果**再检查一遍
5. **把本机 Access Secret 读进内存，逐个文件比对包里有没有它** + 在临时目录里真的起一个进程探 URL
6. 跑一遍仓库契约自检

**期望输出**：`结论：自动可判的项全部通过`

产出两个文件，都要留着：

- `dist/deploy/congxin-<commit>-<时间>.zip` —— **上传这个**
- `dist/deploy/部署预检报告-<commit>-<时间>.md` —— **9 条检查的对照表**

> ⚠️ 这一步**不烧知乎额度**（探测用的是假凭据，不真调上游）。

3. 观察构建状态。

**如果平台要你填构建/启动命令**：

| 项 | 值 |

## 3. 密钥怎么给（最容易卡住的一步）

**原则：密钥绝不进 ZIP、绝不进仓库。**（官方提交前检查第 6 条）

后端按**这个顺序**找凭据（见 `server/src/config.js`）：

| 优先级 | 方式 | 怎么配 |
| --- | --- | --- |
| 1 | 环境变量 | 平台环境变量里加 `ZHIHU_ACCESS_SECRET` = 你的 Access Secret |
| 2 | 环境变量指文件 | 平台环境变量里加 `ZHIHU_ACCESS_SECRET_FILE` = 那个文件的路径 |
| 3 | 约定路径 | 把密钥放在 `secrets/access_secret`（或 `.secrets/access_secret`、`/etc/secrets/access_secret`） |

> 官方口径是「**秘钥写入文件直接构建**」——所以 2、3 两种也支持，
> 就是为了平台不一定把密钥塞成环境变量的情况。

**怎么知道配对了**：打开 preview 链接 → **左栏「材料」列表有真实收藏条目** = 配对了。
如果那里显示「知乎凭据没配好或已失效」= 平台没注入成功，回去查平台的环境变量配置。

> **没配对也不会白屏**：服务照常起、页面照常加载，缺凭据的接口会回
> **真实的中文错误提示**（不会返回假数据）。这是刻意的：
> 崩成 CrashLoop 的话，评委打开链接是一片空白，比报错更糟。

**Access Secret 在哪拿**：<https://developer.zhihu.com/profile>（本机已有，在
`C:\Users\steam\.zhihu-cli\access_secret`，仓库外、gitignore）。

## 4. 端口

- 后端读环境变量 `PORT`，默认 8787。
- **本机 8787 绑不上**（系统拒绝），本地开发要用 `18787`。
- 平台一般会注入 `PORT`；**如果平台用的是别的变量名**，
  就在平台环境变量里手动加一条 `PORT=<平台给的那个端口>`。

## 7. 出事了怎么办

| 现象 | 大概率原因 | 怎么办 |
| --- | --- | --- |
| 构建失败 | 平台没装依赖 / 用了别的构建命令 | 构建命令设 `npm run build`，安装命令设 `npm ci` |
| 容器一直重启 | 端口没对上 | 平台环境变量加 `PORT=<平台给的端口>` |
| 页面能开但没有收藏 | 密钥没注入成功 | 见第 3 节；页面上会明说「知乎凭据没配好或已失效」 |
| `/web/` 404 | 静态没挂上 | 检查 `WEB_STATIC=off` 有没有被设上；正常应挂 `/web/` 与 `/assets/` |
| 素材不显示 | `assets/` 没进包 | 重新跑 `node scripts\pack-deploy.js`，看清单里有没有 `assets/kanshan/` |
| 卡片接口报额度用完 | 知乎额度用完了 | **每日 00:00 重置、不结转**；等次日，或用缓存 |
| 拿不到正式链接 | 内容审核没过 / 还在审 | 审核时间不可控 → **卡在 12-04 前** |
