## 1. 当前命题

做一个"数字桌宠"，核心体验是把用户手上的资料变成**可检索、有出处、真的帮人理解**的知识卡片。
队友的原始提案叫《Agent Pet OS》，包含 9 个概念（具身化智能体 / 吞噬与知识内化 / 具象化建房子 / 装备与专家系统 / 点头授权 / 多宠物生态 / 老板视角与多Agent团队 / 个人数字分身 / 多平台与社交），外加一套企业级工程目录。

**这 9 项不可能全做**，也不该全做。选题收敛的目标不是砍功能，而是选定一条能同时满足三个条件的路径：

1. 官方赛道明确收录（桌宠 → **AI × 陪伴与交互**）
2. 在 19 天内能做出评委能独立跑通的闭环
3. 评分权重最高的两项（AI 场景价值 40% + 创新度 25%）能被真实拿到，而不是靠设计感（10%）补

### 1.1 形态与主次关系（已定，见 decisions.md D10 / D14）

- **形态**：Web 应用，做成可安装 PWA（独立窗口 + 图标 + 桌宠悬浮层）。首版不做 Tauri 桌面端。
- **主次**：**桌宠是交互主体**（有人格、有情绪、有反馈），**知识卡片是它的产出物**，**知乎能力是它的信息来源**。
- **为什么是这个主次**：S2 一等奖 "MeetMind学脉" 已经占了"把收藏资料变成学习内容"这个位置。若做成"卡片生成器 + 宠物皮肤"，会被读成 MeetMind 的降级版，创新度直接失分。S3 首次单列"AI × 陪伴与交互"赛道，上届无对等获奖形态——桌宠路线才是结构性机会。
- **由此得到的差异点**（写进计划书"核心创新"）：
  1. **有出处的观点对照**：不给 AI 黑盒摘要，给**知乎上真实的不同答案及其链接**，让用户看到分歧本身。
  2. **问题反哺**：桌宠能指出"你这个主题，知乎上正在被问的问题"，把私人资料与公共讨论连起来。
  3. **陪伴而非工具**：桌宠对状态有反应（吞咽、思考、打盹、答错后的沮丧），让"整理资料"不再像 chores。

### 1.2 视觉实现路线（已定，见 decisions.md D11）

2D 桌宠用 **SVG 图形 + CSS / Framer Motion** 做状态动画（呼吸、眨眼、拖拽反应、咀嚼、吐卡片）。
**不用** Pixi.js 骨骼动画 + Matter.js 物理引擎 + 力导向图布局——在 38 人时预算下这三样加起来要 2—3 天，而 SVG 方案约 1 天且演示效果足够。

### 1.3 角色设定（已定，见 decisions.md D19）

桌宠主体用**知乎官方 IP 刘看山**，官方 6 个动作按应用状态一一映射（电波→thinking 等）。
备选：自定义宠物（用看山工作台 `custom-pets` 规范：1536×1872 / 8列×9行 / 每帧 192×208）。
状态机与素材解耦（D20），换素材不改业务代码。
**2026-11-17 与队友对齐通过：沿用官方刘看山**，队友未提出自建形象（且原提案中本就无角色设计，因此无沉没成本）。

## 2. 目标用户假设（待验证）

**首要人群**：正在做课程报告、毕业设计或求职准备的 **Windows 大学生**。
附加行为条件（三个同时满足才算命中）：① 经常收集 PDF/网页/AI 回答但事后找不回；② 有一个明确任务（写报告 / 比较方案 / 准备面试）；③ 愿意让桌宠常驻桌面。

**次要人群**：知识型创作者。对引用、导出、稳定性要求更高，放第二轮。

**反例**：没有明确使用任务、只因为"第二大脑"概念好看就想搭的人。这类用户会把时间花在配置上，不产生评审要的"真实用户痛点"证据。

## 3. 核心场景假设

一个具体到可以在几分钟内演示、结果可以被检查的流程：

> 用户带着"我该选 RAG 还是微调"这样一个真实问题，把手头的资料（PDF / 网页 / Markdown）拖进桌宠 →
> 桌宠生成少量卡片，每张卡片都能点回**原文出处** →
> 用户追问"知乎上有哪些不同观点"，桌宠先用 **question recommend** 找到这个主题下知乎正在被问的问题，再用 **question answers** 取出真实回答的摘要与**原始链接**，补上带链接的社区观点 →
> 用户把认可的卡片放进"知识小屋"，之后能检索、能导出。

这条链路的三个设计意图：

- **"带出处"**直接对应评审的"完成度"与"AI 场景价值"：卡片若不可回溯原文，就是不可信的产品。
- **"知乎补观点"**是把知乎生态变成不可替代的核心环节，而不是装饰。官方 CLI 文档明确"搜索用于取得原始资料，直答用于快速获得总结，**深度研究、事实核查和观点比较不要用直答替代搜索**"——所以主路径用 `question recommend` + `question answers`（返回原始回答链接），直答只做快速解释与兜底。
- **"能找回"**回应了上一轮调研的核心争议——"整理好了，是否真的帮你理解"。仅靠 AI 总结资料不能证明这一点，用知乎的真实多观点补足认知才可能。

## 4. 首版范围候选

| 保留 | 理由 |
| --- | --- |
| 吞噬（拖入资料 → 提取文本） | 没有输入就没有闭环。**PDF 解析改用前端本地 `pdfjs-dist`**（官方 `tools` 为 10 次/天，决赛演示够用但撑不住 12-05—12-19 运营期的连续上传，见 D23 / D24）；输入以「文本/Markdown 粘贴」+「网页链接」为主，PDF 为可选入口，提取失败给真实提示 |
| 卡片生成 + 每张卡带原文出处 | 场景成立的核心 |
| 知乎能力接入（`question recommend` / `question answers`） | 评审 40% 权重 + 官方生态契合度；`question recommend` 还能做"问题反哺"。**直答只兜底**（理由是"观点比较"必须用能返回原始链接的接口，与额度无关）、**热榜首版不做**（主线关联弱 + 预算）。实名认证后额度与官网标称一致，主路径不受限 |
| 轻量"小屋"视图（卡片可归置、可检索） | 回应"能找回"，不需要完整图谱引擎 |
| 宠物形象与基础交互反馈 | 赛道要求 + 10% 设计感 + 决赛直播演示观感 |
| 知乎 OAuth 登录 | 登录人数直接计入人气奖产出 |

| 本轮排除 | 依据 |
| --- | --- |
| 多宠物生态 / 多 Agent 团队 / 老板视角 | 无真实任务需要不同能力并行，反而增加配置与监工成本 |
| 个人数字分身 / 长期记忆 | 无法在比赛期内证明"越用越准" |
| 多平台与社交 / A2A | 需要微服务隔离与独立网关，成本与收益完全不成比例 |
| 装备与专家系统（插件生态） | 需要插件清单 Schema、权限模型与沙箱执行器 |
| 知识图谱 / Neo4j / 双向链接自动生成 | "自动生成双向链接"只证明资料被连接了，不证明用户能理解和回忆 |
| Kafka / Redis / K8s / 微服务拆分 | 官方部署口径明确劝退多中间件方案；**单进程进程内 Map 存会话即可**，单机/Serverless 更稳 |
| 云原生沙箱删除文件（清道夫） | 涉及不可逆操作，演示风险与安全争议远大于收益 |
| Pixi.js 骨骼动画 / Matter.js 物理 / 力导向图布局 | 38 人时预算下要 2—3 天，SVG + CSS 方案 1 天且够用 |
| Tauri / Rust 打包与跨平台分发 | 吃掉 25%—30% 预算，换来的只是安装门槛；且 OAuth 与人气奖只对 Web 友好 |

## 5. 首版验收条件（可判定的）

1. 评委在**无本地开发环境**的浏览器里点开链接，能在 3 分钟内完成"投资料 → 看卡片 → 点开原文 → 追问知乎观点 → 归置保存"全流程。
2. 每张卡片都显示来源（文件 + 原文片段或知乎回答链接），可点击回跳。
3. 知乎能力调用失败、超时、被取消、额度耗尽时，界面显示真实失败原因并允许重试，**不返回任何伪造的兜底数据**。
4. 登录功能提供可直接使用的测试账号，不暴露真实用户数据；测试账号不复用个人或生产管理账号。
5. **App Key / Access Secret / OAuth Token 不出现在源码、前端响应、日志、截图或视频中。**
6. 官方提交前检查 9 条（见 [rules-知乎S3.md](rules-知乎S3.md) 12.4）逐条可判定通过。
7. 有 3—5 名符合第 2 节条件的用户用**自己的真实材料**跑过一次，有记录（完成时间、引用是否正确、中断点、是否次日主动再来）。
