这版 3D 我看完了，四间房那版确实更有"家"的感觉，方向我认。但有一点要先定下来：不推翻现在的页面，做成并存 —— 3D 当入口和氛围层，现有工作台当功能和证据层。

原因很简单：我们真正值钱的是知乎真实数据这条链路（收藏 → 卡片带出处 → 同题两答 → 问它给方案和依据），这块在后端和现有工作台里，3D 里现在一个都还没接；书房那些 session/materials/cards/feedback 是 mock，而且照抄的是已经下线的认知闭环那套。所以 3D 不用替换工作台，把"家"搭出来、再从房间里把人领到工作台做正事就行。

具体要改的地方（都对着真实接口）：

1. 挂画墙 / 相框 → GET /api/behavior/favorites。一张相框 = 一条真实收藏（标题、作者、内容类型），点开跳知乎原回答。现在挂本机照片那部分留着当"自己的照片"也行，收藏另起一组。
2. 书桌 / 书架 → POST /api/cards。喂出来的知识卡片 + 出处角标。
3. 书房里那张纸（判断面板）→ POST /api/cards 带 same_question=true，做同题两答。
4. 床头灯 / 书架上的本子 → POST /api/advice。「问它」：抛一件事 → 知乎找相似困境 → 判断适不适合 → 给方案，每步标"依据第几条"，点依据跳原文。
5. 灯串 / 窗外天空 → GET /api/tone。桌宠说话只从这里取，14 句契约台词，一字不改、不新增第 15 句。
6. 门 → 房间切换，你已经做好了，保持。
7. 落地灯 / 地毯 / 拖鞋 / 窗帘 → 纯氛围，点开只给"这个物件怎么做出来的"制作说明卡就行。

三条硬规矩：

- 凡是看起来像"你的经历、你的收藏、知乎上有人说过的话"的内容，必须来自接口。blurb / tips 只能是"这个物件怎么做出来的"这类创作者说明，不能当成用户数据。
- 接口空了就显示真话（这次没读到知乎上的数据），不要用 mock 填坑。
- mockData 里的 moodCurve（情绪曲线）和 unresolvedTensions（未解张力）我们没有接口，先删掉，或者明确标成本地状态。

两个要一起验的技术点：

- three.js 现在走 unpkg 的 importmap，正式环境能不能跑 importmap 我们还没验过，国内网络也不一定通 —— 建议 three.js 本地内置，或者换国内 CDN。
- 手机上 2600 根毛簇 + cloth() 窗帘 + 程序化贴图会不会卡也要测，评委可能用手机打开。
