## 1. 一句话

**收藏/关注看「用户在关心什么」（主题分类，6 类），创作看「用户怎么表达」（论证结构，5 类）——两套不是同一根轴，不要混。**

分类体系是**跨两个人的接口**：后端算出来、前端要显示并高亮。口径必须只有一份，所以放契约层。

## 3. 论证结构分类（创作专用）

| id | 名称 | 回答什么问题 |
| --- | --- | --- |
| `problem_solution` | 痛点式 | 先摆现状问题，再给方案 |
| `definition` | 定义式 | 先把概念界定清楚 |
| `contrast` | 对比式 | A 与 B 摆在一起比 |
| `steps` | 步骤式 | 怎么做，按顺序来 |
| `example` | 举例式 | 用案例把道理讲出来 |

**本次真实结果**：创作只有 **1 条**（pin《从心--ai宠物》），规则判定为 **痛点式**——"我的收藏夹里有 200 篇 PDF，一篇都没用上" → "我要做个会吃东西的桌宠"。

⚠️ **但这个结论很弱，原因有三，逐条记清楚**：

1. **样本只有 1 条** —— 接口必须如实返回 `sample_note` 说明样本不足，**不许拿 1 个样本编一个分布**。
2. **「痛点式」与「步骤式」同分**（各 1 分，命中词分别是「没用」「流程」）——痛点式胜出只因为**类目数组顺序**排在前面。
   后端已在 `sample_note` 里写明同分，返回体也带 `tied` / `tied_with`。
   **换个人、换个词表，这个结论就可能翻。**
3. **上游摘要被截断** —— 上游返回的 `Summary` 末尾是省略号（截在「…事后…」），**只覆盖了原文的一部分**。
   基于摘要的分类因此是"读了一半的判断"，不是完整判定。

> **修正记录**：本节早先写的是"人工判读为痛点式"，但那时**规则实际判出来的是「步骤式」**（命中「然后」「流程」），
> 文档与代码不一致。现已收紧关键词规则（见 5.1），两者一致，且把"同分"这件事明写出来。详见 `docs/decisions.md` D30。

## 4. ★ 断层原料：这次真实数据里已经有一组现成的

| | 自述（用户写的） | 行为（真实数据） |
| --- | --- | --- |
| 表面倾向 | 长期主义、体系化、深度 | 收藏 44% 是**装得上、跑得起来、立刻能用**的工具；22% 是**怎么写对**的工程方法 |
| 节奏 | —— | 778 天跨度，但**只有 6 天在收藏** → 任务驱动，不是持续探索 |
| 意外 | —— | 收藏里有一条**清明梦的个人故事**（跟知识工作无关） |

**而用户自己在创作里写着**：

> "我的收藏夹里有 200 篇 PDF，一篇都没用上。"

→ **收藏 ≠ 使用，这件事不是我们编的洞察，是用户自己写出来的。** 这就是「认·清」要撞的那个东西，也是这个产品第一句话的素材。

> ⚠️ **上表的"自述"一栏是空的**——因为它取决于用户实际的自测结果，**现在不能替用户填**。
> 这正是 `POST /api/behavior/tension` 要做的事：拿真实的自述去撞真实的行为。
> **文案模板必须留空位等真实数据，不能预写结论。**

## 5. 判定规则

1. **标题命中一个关键词记 2 分，摘要命中记 1 分**，同一关键词重复出现不叠加。
2. **摘要只取上游给的官方服务摘要（约 200 字）**，不是全文；**而且上游可能把摘要截断**（末尾带省略号）——截断了要在提示里说明。
3. **分数 < 1 → 未归类**。这是合法结果，前端显示「未归类」，**不许为了凑占比硬塞**。
4. **分数相同按类目数组顺序取先者**，并在证据里写明命中了哪些词——**前端要能解释为什么归到这一类**。
5. **同分即弱结论**：第一名与其它类同分时，只是数组顺序取胜。返回体带 `tied` / `tied_with`，提示里必须写明，
   **不能把"同分"说成"集中在某类"**。
6. **每条内容必须能指回原文 URL**，分类不能是黑盒断言。

### 5.1 关键词表（初版，踩过的坑都改了）

| 改动 | 为什么 |
| --- | --- |
| 知识管理去掉裸「笔记」 | 会命中「UML …已收录至专栏…学习笔记」的**摘要**，把建模文章误判成知识管理 |
| 认知去掉裸「思维」 | 会命中「**思维导图**软件哪个好」——那是工具选型，不是认知方法 |
| 工具加「思维导图」「选型」 | 补回上面那条 |
| 知识管理加「收藏夹」「清理」 | 「请大家不要随意尝试清明梦」那条其实是**故事分享**，不是收藏夹整理（人工标注已按真实摘要更正为「未归类」） |
| 关注类加英文词（`learning by doing`） | 关注的信号源只有「名字 + 一句话签名」，纯中文关键词命中不了英文签名 |
| 资讯加「日报」 | 「知乎日报」这个关注对象必须能归到资讯 |
| **步骤式去掉「然后」** | 「然后」是中文里的连接词，**几乎每段都有**，留着会让「步骤式」到处误命中。结构标志应该是「第一步/首先/接着/最后/依次」这种**序列词** |
| **步骤式去掉「方法」** | 太泛，而且跟认知类的「方法论」打架 |
| **痛点式把裸「缺」换成「缺少」，并加「没用」** | 裸「缺」会误命中「**缺省值**」「**缺陷**」这类工具类术语；「没用」「没用上」是中文技术写作里最常见的痛点陈述方式 |

> 上面三条改动是在 **2026-11-17 22:5x** 做的，动机是发现**文档与代码不一致**（见第 3 节的修正记录），
> **不是为了让某个样本好看**——收紧后「痛点式」仍然只是**同分弱结论**。

## 7. 待与队友确认的三件事（B14 的真正待办）

1. **这 6 类够不够用、名字顺不顺口？** 特别是「工具与环境」和「工程与方法」的边界——很多内容两边都能沾。
2. **「未归类」在界面上怎么显示？** 我的建议是**显示成「未归类」并给一句解释**（"这条不属于任何知识类"），**不要隐藏**——隐藏了占比就骗人了。
3. **分类体系要不要进「计划书」？** 我的建议是**进**，而且要写明这是**关键词规则 + 人工基线校准**，不是玄学。评审看完成度 25% 与场景价值 40%，"我们怎么把行为变成信号"讲清楚了是加分项。

## 8. 已知限制（诚实记录）

- **样本量很小**：收藏 9 条 / 关注 3 个 / 创作 1 条。**占比只能当 demo 用，不能当统计结论。**
- **关注的信号源太弱**：只有名字 + 一句话简介，命中率天然低。真实产品里可能要结合该用户的历史内容主题，那要额外调用，成本另算。
- **摘要只是官方服务摘要（约 200 字）**，不是全文。摘要里的词会污染分类——权重比已经压到 1:2，但没法根除。
- **上游会把摘要截断**（实测创作《从心--ai宠物》截在「…事后…」）。所以**基于摘要的分类只覆盖原文的一部分**，
  论证结构这一层尤其受影响。后端已在 `sample_note` 里写明截断条数。
- **同分即弱结论**。分类是"每条内容只进一个桶"，所以"痛点式 / 步骤式同分"这类情况**在分布里看不出来**——
  现在靠 `tied_with` 字段暴露出来，前端要显示出来。
- **关键词规则本身很脆**。换个用户、换个领域就得调。这是有意的取舍：19 天预算里，**可解释的关键词规则 > 不可解释的黑盒模型**。
