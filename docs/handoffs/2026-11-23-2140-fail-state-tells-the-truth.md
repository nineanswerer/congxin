## 3. 试过但没成的（**最重要，别省**）

1. **一度以为新标题没生效 —— 其实验的是另一个标签页的旧代码。**
   中途有个标签页是 `http://localhost:18800/web/?demo=1&fast=1`（演练页），
   它加载的是**浏览器缓存里的旧版 `app.js`**。在那页上点「让桌宠照照镜子」，
   界面印的是旧标题「**信号不够，断层不成立。**」，
   而我抓到的响应体里 `data.warnings` **明明有** `self_report_not_comparable`。
   排查了整整一轮（`getTension` 直调 → `warnings` 数组正常、`.includes()` 表达式正常、
   服务端发的 `app.js` 也是新的），最后是 `reload` 之后看 URL 才发现**活动标签页根本不是我点的那个**。
   → **教训**：
   - **验前端改动必须开新标签页**（或加 cache-busting 参数，如 `?verify=1`），
     **浏览器会缓存 `web/js/app.js`**；
   - `run_script` 回报的 URL 是**当前活动标签页**的 —— `open_tab` 之后要确认活动标签页是哪个，
     别以为「我刚才 open_tab 的那个」就一定还是它。

2. **手写 API 直测时把问卷选项的 traits 记错了。**
   我一直以为 **q5 的 C 选项**是「关系 / 共情」，其实 **A 才是「关系 / 共情」，C 是「逻辑一致」**。
   于是我第一次的对照组 payload 与问卷真实产出的 traits 对不上，一度以为后端判定有误、
   甚至以为「16 种答法」的结论是错的。
   → **教训**：**对照组 payload 必须从页面真实算出来的 `scoreQuiz` 取**，
   最好用 `run_script` 在页面里 `await import('/web/js/quiz.js')` 现算，**别凭印象手写 traits**。

3. **两个服务都自灭了。**
   18800（带密钥）跑满 **1 小时硬上限**后自己退出，18801（坏密钥）也一起没了，
   中途 `fetch` 直接 `fetch failed`。
   → **教训**：`/api/health` **不存在**（404），探活用 `/api/quota`；
   每次开测前先确认两个服务都活着，测到一半失败时先怀疑它自灭了，别急着查代码。

4. **枚举 729 种答法这件事，本身就是这次改动的触发点。**
   只看几条典型答法（全是「深度型」词）永远发现不了「16 种 traits 全空」的答法 ——
   必须**穷举**才能把「一个可比维度都没有」这种情况捞出来。
   穷举结果：q1∈{B,C} × q2∈{B,C} × q3=B × q4∈{B,C} × q5∈{B,C} × q6=B = **16 种**。
