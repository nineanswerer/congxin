## 3. 试过但没成的（**最重要，别省**）

- **尝试**：在 `scripts/check-contract.ps1` 里加一条"每个平台指针文件必须包含 `BOOTSTRAP` 字样"的检查。
  **结果**：**FAIL** —— `.gemini/settings.json` 只有一个 `context.fileName` 字段，装不下两个文件，而 Gemini 的 context 文件只能指向一个。
  **结论**：检查要验**指针链能不能走通**，不是验关键词。改成"指针文件指向 AGENTS.md，且（自己含 BOOTSTRAP **或** AGENTS.md 含 BOOTSTRAP）"即算通过。**Gemini 走两跳，其余四个走一跳。**

- **尝试**：用 PowerShell 跑 hook 实测时把 `$ErrorActionPreference` 设成 `'Stop'`。
  **结果**：hook 往 stderr 写提示信息，PowerShell 把它当异常，整个测试脚本在**第一个用例之后就中断**，后面的用例根本没跑。
  **结论**：测 hook 的脚本里 `$ErrorActionPreference` 必须设 `'Continue'`，否则"被拒绝的用例"会把测试自己打断。

- **尝试**：在 `commit-msg` hook 里用 `awk -v v="$CTX_PENDING"` 传值。
  **结果**：理论上 `awk` 会把 `-v` 的值当转义序列处理，反斜杠会出问题。
  **结论**：先 `tr '\\' '/'` 把反斜杠换掉再传给 awk。

- **尝试**：把"人要说的话"设计成让 AI 自由填写 `.ctx/current.md`。
  **结果**：违背"Context 必须人给"的初衷——AI 自由写就会变成推断。
  **结论**：协议里写死"**只转录人明确说过的理由，人没说过就留空让人补**"，hook 只在 `Context:` 缺失时才用 `.ctx/` 的内容。

- **尝试**：把 BOOTSTRAP / HANDOFF 正文复制进 5 个指针文件。
  **结果**：**没有做**——这会制造 5 份正文，正是本项目 AGENTS.md 第 1 节禁止的"正文有两份就会漂移"。
  **结论**：改为指针文件只写一行"读 `prompts/BOOTSTRAP.md`"，协议本体只有一份。
