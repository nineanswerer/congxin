## 3. 试过但没成的（**最重要，别省**）

- **尝试**：把 GitHub 仓库直接改名为中文 `从心`。
  **结果**：422 `name already exists on this account`。换成 `从心x` 后**请求成功，但真名变成 `-x`**。用 `POST /user/repos` 新建 `从心` 同样 422；`GET /repos/nineanswerer/从心` 返回 404；列全部 27 个 owner+collaborator 仓库，**含非 ASCII 名的 0 个**。
  **结论**：**GitHub 会把仓库名里连续的非 ASCII 字符规范成一个连字符。**`从心` → `-`，撞上账号里已存在的 `-` 仓库（desc="看漫画html文件"），所以报"名字已存在"。那两个怪仓库 `-` 和 `-claude-` 就是历史遗留的同款现象。
  **→ 下一个 AI 不要再试中文仓库名，也不要去动那两个 `-` / `-claude-` 仓库**（属于用户的其他项目，与本项目无关）。**即使腾出 `-`，仓库也只会叫 `-`**，URL 变成 `github.com/nineanswerer/-`，毫无意义。

- **尝试**：把仓库改回中文名时，第一次报"名字已存在"，改用纯 ASCII 名 `congxin-rename-test` 成功后立刻改回。
  **结果**：报 `a conflicting repository operation is still in progress, orchestration in progress 1628711123` —— **GitHub 的改名是异步的，改完立刻改第二次会撞上编排锁**。
  **结论**：连续两次改名之间要**等 10 秒以上**；报 "orchestration in progress" 时等待重试即可，不是名字有问题。

- **尝试**：判断"名字已存在"是不是因为账号真有某个中文名仓库，于是反复列仓库、跑 search API、逐个试候选名（`从心x` / `x从心` / `从心-` / `congxin` / `从心2`）。
  **结果**：**绕了远路**——先后触发 4 次 422，做了 8 次 API 探测，中途把仓库临时留在了 `-x` 这个破名字上。
  **结论**：**判断平台行为时，先用一次性测试仓库试，不要拿正式仓库试。**或者直接用一次"改名到 X 再看真名"的实验定位规范化规则。用户在这次之后明确说"GitHub改名不能用中文，你为什么不知道" —— **这条属于"应当事先知道/先查"的常识，下次先查再动手。**

- **尝试**：在 `docs/队友对齐清单.md` 的零 D 表格里新增一行"那份方案文档不能公开"的状态行。
  **结果**：**与原有那一行重复**（表格出现两个同 key 行）。
  **结论**：改前先用 grep 看该 key 是否已存在；本项目的表格一行一意，重复行会让"照抄即可"的话术出现两个版本。

- **尝试**：在 `docs/decisions.md` 里改写 D18 的"待定 / 待授权"两行。
  **结果**：直接替换会丢掉历史语境，违反本项目"L2 只增不改"的纪律。
  **结论**：用 `~~删除线~~` 标注作废并指向新决策号，**保留原文**。
