## 3. 试过但没成的（**最重要，别省**）

- **尝试**：一次性把 P1 的 5 分钟脚本压成 2 分钟。
  **结果**：**漏了 P1 §2.1 的 `offer` 和 §2.2 的 `park` 两句台词** —— 我压时间轴时把这两拍整个吞掉了。
  **暴露方式**：写了校验器比对 `tone.json`，发现「温和陪伴 14 句里只用到 7 句」，而按 D68「认知闭环下线后不调用的是 5 句」应该用到 **9 句** → 差的正是 `offer` 和 `park`。
  **结论**：**压时间轴不能靠感觉压，必须用台词目录做覆盖度反查**。已把校验器固化成「已用句集合 + 应未用句集合」双向断言。

- **尝试**：用同一个正则去校验整篇分镜文档的引号内容。
  **结果**：**53 条误报** —— 正则把「口气提醒」里的反例词（「观点相反」「你的收藏」）、章节名、以及带 markdown 星号的粗体引用（`**这些办法对你适用**`）全当成了台词。
  **结论**：**校验器必须限定区块**（只查「气泡核对表」），并且**界面文案不能拿台词目录去比** —— 那是三套不同的真值源（`tone.json` 台词 / `app.js` 固定文案 / 实跑首屏文案）。

- **尝试**：猜「这些办法对你适用」「依据 N、M 条」这两处界面文案。
  **结果**：没猜。`grep '适用|依据' web/js/app.js` 拿到真值：
  - `app.js:867` → `applicable` → **「这些办法对你适用」**
  - `app.js:868` → `partially_applicable` → **「部分适用 —— 挑着看」**
  - `app.js:959` → **`依据 ${nums.join('、')} 条`** → 实际渲染成「依据 1、3 条」（编号顿号分隔）
  **结论**：**引用界面文案前先 grep 一次**，别照抄别的文档里的转述。

- **尝试**：把「问它」的等待过程（实测 13—20 秒）完整录进视频。
  **结果**：**画面会显得卡**。
  **结论**：**用缓存预热**（提前 5 分钟问同一个问题）→ 录制时秒出；要拍"等待"就**另录一遍未预热的**，后期把「等待 3 秒 + 结果」剪在一起，**不加速、不伪造**。
