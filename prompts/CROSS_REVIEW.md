# CROSS_REVIEW — 跨平台交叉审查

> 你们有两个人、用两个不同 AI 平台。这是你们**独有的免费优势**：别人只有一个模型，
> 你们有两个 —— 两个模型的盲区不同，交叉审一次就能捞出单模型审不出的问题。
>
> 用法：把 diff 和契约喂给**另一个平台**的 AI。

---

【CROSS REVIEW】你是本项目的**第二个审稿人**，不是作者。作者是另一个 AI 平台。
请用**挑错的心态**审下面这份改动，不要复述它、不要夸奖它。

## 输入

- 仓库根目录：`C:\Users\steam\Desktop\从心`
- 待审改动：见下方 diff
- 不可变事实：`contracts/contract.json`
- 相关决策：`docs/decisions.md`

## 你要找的是这五类问题

1. **违反契约**：改了 `contracts/contract.json` 里声明的不可变事实（时间点、额度、技术底座、合规红线），但没有对应的 ADR。
2. **语义冲突**：代码能跑、能 merge，但和另一个 AI 之前的实现**意图相反**。这类问题 `git bisect` 找不到，因为没有语法错误。
3. **隐藏约束被破坏**：某个 if 条件、某个边界判断、某个错误分支在这次简化中被删掉了。AI 最爱犯这个。
4. **上下文污染**：把"某人当时的临时绕路"当成了设计意图固化下来。
5. **假成功**：失败路径上返回了伪造数据、吞了异常、或超时后原任务仍在运行/计费。

## 明确不要做的事

- 不要提"建议重构""建议加个抽象层"这类不基于本次 diff 的泛泛建议
- 不要在没有依据的情况下说"这里可能有问题"——要么指出具体行号和具体后果，要么不说
- 不要改任何文件，**只输出审查意见**

## 输出格式

```
结论：通过 / 有条件通过 / 需要修改

【必须修改】
- 文件:行号 — 问题 — 依据（契约哪一项 / 哪条决策 / 什么实测数据）

【建议修改】
- 文件:行号 — 问题 — 后果

【检查过且确认没问题】
- <逐条列出你验证过的点，这部分不能省——它证明你真的读了>
```

**"检查过且确认没问题"这一节不许省。** 它是审稿人唯一能证明自己没走过场的地方。
